# 울산 중심 관광지 추천 — 2026-09-18

## 적용 내용

울산/울주 여행의 ‘중심 관광지 담기’에 **맞춤 추천순 / 인기순 / 이름순**을 추가했다. 기존 PC 사진 카드와 관광지 선택 → 관람시간 지정 → 대주제 일정에 담기 흐름을 사용한다. 다른 지역은 기존 TourAPI 검색을 유지한다.

- 인기순: 해당 관광지의 데이터랩 검색건수 내림차순. 같은 건수는 이름순.
- 맞춤 추천순: 해당 관광지 방문자 중 선택한 연령·성별의 비중 내림차순. 같은 비중은 인기순. 성별 전체는 같은 연령대의 남녀 비중 합계.
- 이름순: 한국어 이름순.
- 전체 후보를 정렬한 다음 20개씩 페이지를 나눈다. 카테고리(전체/관광지/문화시설/레포츠) 및 검색어 필터와 함께 적용한다.
- 검색건수는 실제 방문자 수가 아니다. 성·연령 비중은 이용자의 만족도나 방문자 절대수가 아니다. 화면에 근거를 표시한다.

## 데이터와 연결 범위

사용자가 제공한 울산 5개 구·군 CSV 10개. 조회 기간은 사용자 확인값 **2025-09~2026-08**. 다운로드 폴더 `202609`와 구분한다. 방문자 전체/현지인/외지인 조건은 제공되지 않았으므로 `unspecified`로 보관한다.

| 자료 | 원본/수집 건수 | TourAPI 관광지에 연결 |
| --- | ---: | ---: |
| TourAPI 관광지·문화시설·레포츠 | 165곳 | 사진 URL 157곳 |
| 지역별 관광지 검색순위 | 1,660행 | 106곳 |
| 성·연령별 방문 집중률 | 118행 | 98곳 |

TourAPI의 울산 지역 목록 일부에는 최신 관광지가 누락되어, 성·연령 CSV 이름으로 공식 검색 API를 추가 조회했다. 사진은 공식 URL을 사용하고 출처 및 공공누리 유형을 표시한다.

연결은 **같은 구·군 + 공백·일부 기호·(울산)/(울주) 표기를 정규화한 이름의 유일 일치**만 허용한다. 동명 중복 통계는 합산하지 않는다. 공원과 출렁다리 같은 부속시설도 서로 다른 관광지로 둔다. 이름이 다르거나 중복된 자료는 미연결 상태로 보존한다. 따라서 ‘자수정 동굴나라’ 등 일부 장소는 성·연령 자료만 연결되고 검색건수는 없을 수 있다.

미연결 수치를 0으로 만들지 않는다. 카드에 ‘자료 없음’을 표시하며 해당 정렬의 통계가 있는 장소 뒤에 둔다. 검색순위 원본에 있는 역·공항·상점 등을 검색량만으로 관광지 후보에 추가하지 않는다.

## 회원가입 → 추천 연결

일반 가입 및 Google/Kakao/Naver 추가 가입 화면에 생년월일·성별 선택 입력을 공통 적용했다. 기존 `users.birthdate`, `users.gender` 컬럼을 사용한다. 신규 컬럼 마이그레이션은 추가하지 않았다.

- 서버에서 실제 달력 날짜, 미래 날짜, 120년 범위, 허용 성별 값을 검증한다.
- 로그인 세션의 본인 ID로 DB를 조회하고 한국 날짜 기준 만 나이를 연령대로 변환한다. 요청의 `userId`는 신뢰하지 않는다.
- 데이터 원본 구간에 맞춰 10대 이하~70대 이상 7개 연령대를 사용한다.
- 생년월일이 없으면 인기순 대체 안내를 표시한다. 연령대만 있으면 해당 연령대 남녀 합계를 사용한다.
- 관광지 화면에서 추천 연령·성별을 직접 선택하거나 ‘내 회원정보 적용’으로 돌아갈 수 있다. 직접 선택은 회원 DB를 수정하지 않는다.
- 추천 응답에는 생년월일/회원 ID를 포함하지 않고, 연령대·성별·기준 출처만 반환한다. `Cache-Control: private, no-store`를 설정한다.
- 기존 회원정보가 비어 있어도 가입을 다시 할 필요 없이 화면에서 추천 기준을 선택할 수 있다.

## 배포와 실제 계정 테스트

프론트와 백엔드 모두 배포해야 한다. 백엔드의 새 `data/tourism/*.json`, `security/demographics.js`, `routes/tourism/ulsan.js`도 포함하고 백엔드를 재시작한다. 스냅샷을 사용하므로 울산 검색 자체는 매번 TourAPI를 호출하지 않는다. 운영 DB 설정은 기존 설정을 그대로 사용한다.

로컬에는 운영 전용 `config/db.js`가 없어 운영 DB를 사용하는 전체 가입·로그인 검증은 하지 않았다. 실제 핸들러와 SQL 경계의 메모리 DB를 사용해 일반 가입→로그인→추천, 세 소셜 가입→추천, 선택 정보 미입력, 잘못된 날짜 재시도 및 토큰 재사용 거부를 검증했다. 운영 배포 후 회원 생년월일·성별을 입력한 계정으로 울산 일정을 만들고 중심 관광지에서 ‘회원정보 기준’을 확인한다.

### 지금 확인 가능한 로컬 미리보기

`http://127.0.0.1:5198/dev-preview/ulsan-tourism.html`

실제 관광지 데이터·실제 추천 라우터·실제 관광지 선택 컴포넌트를 사용한다. **회원 조회만 20대 여성 샘플**이며 일정 선택은 화면 상태에만 저장한다. 운영 DB 및 운영 계정을 변경하지 않는다. 추천 기준 선택, 정렬, 사진 카드, 관람시간과 선택 결과를 테스트할 수 있다.

백엔드 디렉터리에서:

```powershell
node scripts/preview-ulsan-tourism.cjs
```

프론트 디렉터리의 별도 PowerShell에서:

```powershell
$env:VITE_APP_API_URL='http://127.0.0.1:4318'
npm run dev -- --host 127.0.0.1 --port 5198 --strictPort
```

미리보기 API는 loopback에만 바인딩한다. 일반 앱 서버에서는 이 스크립트를 사용하지 않는다.

## 자료 갱신

백엔드 디렉터리에서 CSV 폴더와 조회 기간을 명시한다. 파일명별 SHA-256 및 행수를 결과 JSON에 저장하며 원본 CSV는 수정하지 않는다.

```powershell
python scripts/import-ulsan-datalab.py '<울산 CSV 폴더>' --start 2025-09 --end 2026-08
node scripts/fetch-ulsan-tourism.cjs
```

TourAPI 갱신에는 기존 `PUBLIC_DATA_SERVICE_KEY`가 필요하다. 키는 결과 JSON이나 로그에 저장하지 않는다. 두 JSON을 검토하고 함께 배포·재시작한다. 프론트 통계 기간은 서버 응답을 표시한다.
