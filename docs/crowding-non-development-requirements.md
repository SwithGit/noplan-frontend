# NoPlan 혼잡도 기능: 개발 외 준비 및 확정사항

- 작성일: 2026-08-08
- 적용 범위: NoPlan 홍대 MVP
- 관련 문서
  - `docs/crowding-integration-plan.md`
  - `docs/crowding-planning-blockers.md`
- 제외 내용: 서울시 및 SKT/TMAP API 키 발급 절차와 실제 키 값

## 1. 문서 목적

이 문서는 혼잡도 기능의 코드 개발 외에 기획·운영·정책 담당자가 확정하거나 확인해야 할 사항을 정리한다.

API 키 발급과 등록 방법은 보안상 별도로 전달한다. 키 값은 이 문서, 채팅 기록, 프론트 환경변수 또는 Git 저장소에 기록하지 않는다.

## 2. 서비스 범위 확정안

현재 NoPlan의 추천 서비스 범위는 `홍대입구·연남동 주변`으로 유지한다.

| 장소 코드 | 장소명 | 현재 사용 여부 | 용도 |
|---|---|---|---|
| `POI073` | 연남동 | 사용 | 연남동 등록 장소의 주변 혼잡도 |
| `POI055` | 홍대입구역(2호선) | 사용 | 홍대입구역 주변 장소의 주변 혼잡도 |
| `POI007` | 홍대 관광특구 | 사용 | 세부 권역에 속하지 않는 홍대 장소의 fallback |
| `POI053` | 합정역 | 보류 | 코드와 Provider 호환만 준비하고 현재 추천·점수에는 미사용 |

합정역 장소가 NoPlan 승인 DB와 사용자 안내 범위에 포함되는 시점에 별도 활성화한다. 현재 첫 화면의 서비스 지역 안내 문구는 변경하지 않는다.

## 3. 사용자에게 보여줄 정보 범위

이번 기능은 정확한 인원수나 특정 매장의 좌석 점유율을 제공하는 기능이 아니다.

사용자에게 제공:

- 권역명
- 주변 혼잡 단계
- 데이터 기준 시각
- 데이터 출처
- 최근 데이터 여부

사용자에게 제공하지 않음:

- 추정 인원 최소·최대값
- 특정 매장의 대기 인원
- 특정 매장의 남은 좌석 수
- 근거 없는 매장 내부 혼잡도
- 통신사 원천 데이터

혼잡 단계는 다음 다섯 가지로 통일한다.

```text
여유
보통
약간 붐빔
붐빔
정보 없음
```

## 4. 표시 명칭 원칙

데이터 범위에 따라 명칭을 분리한다.

| 데이터 범위 | 사용자 표시 |
|---|---|
| 서울시 권역 데이터 | 주변 혼잡도 |
| SKT 상권 데이터 | 주변 혼잡도 |
| SKT 지원 장소 단위 데이터 | 매장 혼잡도 |
| 제휴 매장이 직접 제공한 최신 정보 | 매장 혼잡도 |
| 범위가 불명확한 데이터 | 표시하지 않음 |

서울시 권역 데이터를 특정 매장의 혼잡도로 오해하게 만드는 표현을 사용하지 않는다.

## 5. 출처 및 안내 문구 확정안

장소 카드 표시 예시:

```text
연남동 주변 · 약간 붐빔
18:35 기준 · 서울시 실시간 인구데이터 기반
```

상세 안내 문구:

```text
통신 기반 권역 추정치이며 실제 매장 내부 혼잡도와 다를 수 있어요.
```

stale 데이터 표시 예시:

```text
연남동 주변 · 약간 붐빔
18:05 최근 확인 · 서울시 실시간 인구데이터 기반
```

기획·운영 담당자는 출시 전에 위 문구의 서비스 톤과 출처표시 적정성을 최종 확인한다.

## 6. 추천 반영 정책 확정안

혼잡도는 추천 후보를 제거하는 필수 필터로 사용하지 않는다.

기본 정책:

- 사용자가 `대기 적게`를 선택하지 않으면 혼잡도는 정보 표시만 한다.
- 사용자가 `대기 적게`를 선택하면 상대적으로 혼잡한 권역에 소프트 페널티를 적용한다.
- 혼잡도 정보가 없다는 이유로 장소를 제외하지 않는다.
- 영업 여부, 핵심 목적, 필수 코스 슬롯 유지가 혼잡도보다 우선한다.
- 모든 후보가 같은 혼잡 권역이면 혼잡도 때문에 추천 순서를 변경하지 않는다.
- 오래된 stale 데이터는 정상 데이터보다 약하게 반영한다.

현재 추천 엔진은 낮은 점수가 우선이므로 혼잡할수록 양수 페널티를 추가한다.

| 혼잡 단계 | `대기 적게` 미선택 | `대기 적게` 선택 |
|---|---:|---:|
| 여유 | 0 | 0 |
| 보통 | 0 | +200 |
| 약간 붐빔 | 0 | +600 |
| 붐빔 | 0 | +1,000 |
| 정보 없음 | 0 | 0 |

stale 데이터는 위 페널티의 50%만 적용한다. 실제 사용자 결과를 확인한 뒤 수치를 조정한다.

## 7. 권역 매핑 검수 정책

개발자가 공식 영역 자료와 장소 좌표를 이용해 권역 코드를 자동 매핑한 후, 기획·운영 담당자가 결과를 검수한다.

검수 항목:

- 연남동 장소가 `POI073`으로 매핑됐는지
- 홍대입구역 주변 장소가 `POI055`로 매핑됐는지
- 나머지 홍대 장소가 `POI007` fallback으로 매핑됐는지
- 현재 서비스 범위 밖 장소에 혼잡 권역이 적용되지 않았는지
- 동일 장소가 복수 권역에 매핑되지 않았는지
- 주소 또는 좌표가 비어 있는 승인 장소가 있는지

권역이 겹치는 경우 우선순위:

```text
POI073 연남동
→ POI055 홍대입구역
→ POI007 홍대 관광특구
```

공식 권역 처리가 완료되지 않은 초기 상태에서 모든 홍대 장소가 `POI007`을 사용한다면, 주변 혼잡도 표시는 허용하되 추천 점수에는 반영하지 않는다.

## 8. 화면 검수 항목

기획·운영 담당자는 개발 완료 후 실제 모바일 화면에서 다음을 확인한다.

- `주변 혼잡도`와 `매장 혼잡도`가 혼동되지 않는가
- 정확한 인원수처럼 보이는 표현이 없는가
- 기준 시각이 눈에 보이는가
- 출처가 표시되는가
- stale 데이터가 현재 데이터처럼 보이지 않는가
- 정보가 없을 때 빈 박스나 잘못된 기본값이 나타나지 않는가
- 혼잡도 때문에 장소명, 시작 시간, 예상 체류시간이 잘리지 않는가
- 색상만 보지 않아도 혼잡 단계를 알 수 있는가
- 사용자에게 새로운 필수 입력 단계가 추가되지 않았는가

## 9. 실제 운영 전 관찰 기간

추천 점수 반영 전에 혼잡도를 화면에만 표시하는 관찰 기간을 둔다.

1단계:

```text
혼잡도 화면 표시: 활성화
혼잡도 추천 점수: 비활성화
```

관찰할 내용:

- 데이터가 없는 시간대와 빈도
- 권역 매핑 오류
- 기준 시각 지연
- stale 데이터 발생 빈도
- 사용자가 주변 혼잡도를 매장 정보로 오해할 가능성
- 지역별 혼잡 단계가 실제 체감과 지나치게 다르지 않은지

관찰 결과에 문제가 없으면 `대기 적게` 선택에 한해 추천 점수 반영을 활성화한다.

## 10. SKT/TMAP 무료체험 운영 계획

무료체험의 목적은 전체 장소를 실시간 운영하는 것이 아니라, NoPlan에 실제 가치가 있는지 판단하는 것이다.

확인 항목:

- 계정에 적용된 상품명
- 실제 일간·월간 무료 호출 한도
- 장소 목록 호출이 한도에서 차감되는지
- 홍대 또는 연남동 상권 제공 여부
- NoPlan 승인 장소 중 지원 장소 개수
- 장소명·주소·좌표 기반 매칭률
- 장소 단위와 상권 단위 데이터의 차이
- 실제 갱신 간격
- 평균 응답 시간
- 오류와 한도 초과 응답 형태
- 유료 전환 시 예상 월 비용

무료 호출은 다음 순서로 사용한다.

| 순서 | 확인 내용 |
|---:|---|
| 1 | 지원 장소 또는 상권 목록에서 홍대 검색 |
| 2 | NoPlan 장소 DB와 오프라인 매칭 |
| 3 | 매칭된 대표 장소 소수만 실시간 조회 |
| 4 | 같은 장소를 다른 시간에 재조회하여 갱신 확인 |
| 5 | 미지원 장소와 오류 fallback 확인 |

무료체험 중 전체 NoPlan 장소를 하나씩 실시간 호출하지 않는다.

## 11. SKT/TMAP 유료 전환 판단 기준

다음 중 하나 이상을 충족하고 비용이 허용될 때만 유료 전환을 검토한다.

- 홍대·연남동 상권 데이터가 서울시 데이터보다 유의미하게 세분화됨
- NoPlan 핵심 추천 장소의 의미 있는 비율이 장소 단위로 매칭됨
- 매장 또는 상권 데이터가 서울시 주변 혼잡도보다 명확한 사용자 가치를 제공함
- `대기 적게` 추천 품질이 실제로 개선됨

다음 경우 유료 전환하지 않는다.

- 홍대 지원 상권이 없음
- 장소 매칭률이 낮음
- 서울시 권역 데이터와 차이가 거의 없음
- 무료체험만으로도 데이터 신뢰성이 낮다고 판단됨
- 예상 월 비용에 비해 사용자 가치가 작음

## 12. 장애 및 사용자 안내 정책

외부 혼잡도 데이터가 실패해도 코스 추천은 정상 동작해야 한다.

| 상황 | 사용자 처리 |
|---|---|
| 최신 데이터 정상 | 현재 주변 혼잡도 표시 |
| 최신 호출 실패, 최근 정상값 존재 | `최근 확인`으로 표시 |
| 최근 정상값도 없음 | 혼잡도 미표시 또는 정보 없음 |
| 일부 권역만 실패 | 정상 권역만 표시, 실패 권역은 추천에서 불이익 없음 |
| SKT 데이터 실패 | 서울시 권역 데이터로 fallback |
| 모든 공급자 실패 | 기존 추천 결과 유지 |

장애 상황을 사용자에게 코스 생성 실패로 표현하지 않는다.

## 13. 출시 승인 조건

다음 조건을 모두 만족한 뒤 혼잡도 표시 기능을 출시한다.

- [ ] 서비스 범위가 홍대입구·연남동으로 유지됨
- [ ] 합정역 추천 반영이 비활성화됨
- [ ] 권역 매핑 결과를 검수함
- [ ] 주변 혼잡도와 매장 혼잡도 문구가 구분됨
- [ ] 정확한 인원수를 표시하지 않음
- [ ] 기준 시각과 출처가 표시됨
- [ ] stale 표시가 구분됨
- [ ] 모바일 화면 검수를 완료함
- [ ] 외부 데이터 장애 시 코스 생성이 유지됨
- [ ] 키나 원본 인증정보가 프론트와 Git에 노출되지 않음

다음 조건을 추가로 만족한 뒤 추천 점수 반영을 활성화한다.

- [ ] 표시 전용 관찰 기간 동안 심각한 데이터 오류가 없음
- [ ] 권역별 혼잡도 차이가 실제로 존재함
- [ ] `대기 적게` 선택 시에만 양수 페널티가 적용됨
- [ ] 혼잡도 때문에 필수 슬롯이 사라지지 않음
- [ ] 기존 추천 품질 회귀가 없음

## 14. 담당자별 준비사항

### 기획·운영 담당

- 서비스 범위와 합정역 보류 확인
- 사용자 표시 문구 최종 승인
- 권역 매핑 결과 검수
- 모바일 화면 검수
- 표시 전용 관찰 결과 기록
- SKT/TMAP 무료체험 결과 및 유료 전환 여부 결정

### 개발 담당

- 관련 기획서에 따라 기능 구현 및 테스트
- 외부 키를 서버 환경변수로만 사용
- 실제 응답과 권역 자료 검증
- 권역 매핑 결과 목록 제공
- 장애·stale·정보 없음 테스트 결과 제공
- SKT/TMAP 무료체험 호출 및 매칭률 보고서 작성

### 사용자 또는 서비스 책임자

- 서비스 범위 최종 승인
- 출처·안내 문구 최종 승인
- 운영 서버 환경변수 등록 권한 확인
- SKT/TMAP 무료체험 상품과 유료 전환 여부 결정

## 15. 현재 확정 권장안 요약

```text
서비스 지역: 홍대입구·연남동
합정역: 현재 추천에서 제외
기본 데이터: 서울시 권역 혼잡도
표시 명칭: 주변 혼잡도
정확한 인원수: 미표시
새 사용자 입력: 추가하지 않음
기본 추천 반영: 하지 않음
대기 적게 선택 시: 양수 소프트 페널티
외부 API 장애 시: 기존 추천 유지
SKT/TMAP: 무료체험 결과 확인 후 유료 전환 별도 결정
```
