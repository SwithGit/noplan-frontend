# NoPlan PC·모바일 최소 서비스 구성 제안

작성일: 2026-09-16. 메뉴·화면·데이터 범위 검토용이며 이번 작업에서 서비스 코드는 변경하지 않았다.

사용자 최신 결정: 친구 초대, 편집 권한, 실시간 공동 편집, 협업 충돌 처리, 변경 이력·되돌리기는 다른 핵심 기능 준비 후 진행한다. 기존 개인 여행 저장과 저장 충돌 보호는 유지한다. 이전 v0.2 기획안의 협업 우선순위보다 이 결정을 우선한다.

## 서비스 범위

서울의 장소와 기간 한정 경험을 발견하고, 내 시간에 맞는 여행으로 연결한다.

- PC: 여행 날짜를 정하고 여러 장소·행사를 비교하여 일정을 만든다.
- 모바일: 가까운 장소·행사를 발견하고 코스를 추천받아 현장에서 이용한다.
- 장소, 행사, 코스, 내 여행, 찜은 기기 간 같은 데이터다. 화면 구성과 우선 행동을 다르게 한다.
- 현재 실제 추천 범위는 서울·도보다. 전국·차량·대중교통 일정 최적화가 지원된 것처럼 표시하지 않는다.

## PC GNB 제안

`로고(홈) | 여행 탐색 | 축제·전시 | 내 여행 | 찜 | [여행 만들기] | 로그인/프로필`

| 항목 | 역할과 최소 내용 |
|---|---|
| 홈 | 여행지·날짜로 시작, 이어서 작성할 여행, 서울 지역·테마 여행, 여행 날짜에 맞는 행사 진입 |
| 여행 탐색 | 코스 / 장소 탭. 지역·카테고리 검색, 목록·지도, 상세, 찜, 내 여행에 담기 |
| 축제·전시 | 축제 / 전시 / 공연·행사 필터. 날짜·지역·무료 여부·실내외 필터, 목록·지도, 상세 |
| 내 여행 | 예정·진행·지난 여행 목록, 여행 편집, 날짜별 일정·지도·메모·저장 |
| 찜 | 찜한 코스·장소·행사에서 후보를 고르고 여행에 담기 |
| 여행 만들기 | 목적지·날짜·동행·이동 조건 입력 후 편집기로 이동하는 주요 버튼 |
| 프로필 | 계정·추천 기록·설정. 핵심 GNB와 분리 |

‘주변 코스’는 GNB에서 제외하고 홈의 빠른 추천 및 여행 탐색 안으로 연결한다. 맛집·카페·술집은 장소 카테고리로 제공하며 각각을 GNB 메뉴로 늘리지 않는다. 축제·전시는 기간이 있는 여행 목적이므로 별도 메뉴로 노출한다.

### PC에서 필요한 화면

1. 홈: 발견과 여행 시작.
2. 여행 탐색 목록·지도: 코스 / 장소 전환, 검색·필터.
3. 축제·전시 목록·지도: 선택한 방문 날짜에 해당하는 행사.
4. 장소 상세: 사진, 위치, 설명, 영업·휴무, 가격 정보, 별점·후기 수, 찜·일정 추가.
5. 행사 상세: 기간, 실제 관람 시간·휴무·회차, 장소, 비용·연령, 예약 필요 여부, 원문·예약 링크, 찜·일정 추가.
6. 코스 상세: 순서, 체류·이동, 지도, 날짜에 맞게 변경, 찜·내 여행에 가져오기.
7. 여행 생성·편집: 여행 → 날짜 → 시간 구간 → 장소·행사. 기존 큰 일정과 구간별 AI 추천을 연결.
8. 내 여행 목록·찜·계정.

장소·행사·코스 상세에는 항상 ‘찜’과 ‘내 여행에 담기’ 중 필요한 행동을 제공한다. 이미 만든 여행의 날짜와 구간을 골라 추가하며 행사 날짜 불일치 시 안내한다.

## 모바일 메뉴와 화면

하단 `홈 / 탐색 / 찜 / 마이` 유지. 전체 UI 재설계 없이 필요한 콘텐츠를 기존 구조 안에 추가하는 제안이다.

| 메뉴 | 최소 내용 |
|---|---|
| 홈 | 원본 시안의 추천 진입·배너·카테고리 유지, Local Discoveries, 근처 진행 중인 행사 섹션 |
| 탐색 | 코스 / 장소 / 축제·전시 전환. 지역·날짜 검색, 지도·목록, 상세 |
| 찜 | 코스 / 장소 탭 유지. 행사도 장소 탭에서 ‘행사’ 표시·기간과 함께 구분하고 필터 제공 |
| 마이 | 내 여행, 최근 추천 기록, 계정·설정 |

홈 순서: 위치 → ‘오늘 어디 갈까’ → 채팅 입력 → 서비스 지역 안내 → 빠른 추천 버튼 → 홍보 배너 → 카테고리 → Local Discoveries → 근처 축제·전시. 홈에 ‘지금/10분 뒤’ 입력을 추가하지 않는다.

- Local Discoveries는 기존 요청대로 로그인 후 노출, 별점 내림차순·동일 별점이면 후기 수 내림차순.
- 행사 탐색은 별점이 없어도 노출한다. 날짜 적합 여부를 먼저 확인하고, 가까운 순·곧 종료순 등을 제공한다.
- 기본 장소·행사 탐색은 비로그인 접근을 제안한다. 계정 찜과 여행 저장은 로그인 필요.
- 모바일 전용 중요 화면은 여행 실행 화면: 오늘 일정, 다음 장소, 지도 앱 길찾기, 장소 교체, 다음 일정 시간 확인.
- PC에서 만든 여행은 마이의 내 여행 및 해당 여행일 홈의 이어보기로 접근한다.

## 필요한 콘텐츠·데이터

| 데이터 | 준비 방향 | 우선순위 |
|---|---|---|
| 맛집·카페·놀거리·술집·문화시설 | 기존 서울 카탈로그 활용. 관광 명소·산책·공원도 사용자 탐색에 노출 | 필수 |
| 장소 기본정보 | 주소·좌표·분류·대표 사진·설명·원문 출처, 승인/제외 상태 | 필수 |
| 방문 가능 정보 | 영업시간·휴무·입장 마감·체류시간·가격·예약 링크. 미확인은 별도 상태 | 필수 |
| 축제·전시·공연·행사 | 장소와 연결되는 기간·시간이 있는 별도 행사 데이터 | 필수 |
| 여행 코스 | 공개 코스·검수 코스, 지역·테마·소요시간·장소 순서. 장소 DB와는 다른 콘텐츠 | 필수 |
| 도보 이동 | 장소 간 이동시간과 경로, 다음 일정과의 시간 적합성 | 필수 |
| 날씨·실내외 | 비 오는 날의 실내 코스 대안 등에 활용. 기본 탐색·행사 연결 다음 단계 | 후속 |
| 주차·대중교통·혼잡도 | 해당 이동 방식과 데이터 범위를 실제 지원할 때 추가 | 후속 |
| 숙박·티켓 직접 결제, 자체 후기 작성 | 초기에는 외부 링크와 기존 후기 지표 활용 | 후속 |

기존 카탈로그의 문화·전시 분류는 `activity + detail_type`인 경우가 있으므로 문화시설 조회에 기존 분류 규칙을 유지한다. 이를 행사 개최 정보로 간주하지 않는다.

### 행사 데이터 최소 항목

- 행사명·유형·대표 이미지·설명.
- 시작일·종료일, 관람 시간·휴무·입장 마감, 회차가 있으면 회차 정보.
- 개최 장소·주소·좌표, 기존 장소 ID 연결(매칭 가능한 경우).
- 무료/유료·가격 안내·연령 제한·예약 필요 여부·공식 예약 URL.
- 예정/기간 중/종료/취소 상태, 출처 ID·원문 URL·마지막 확인 시각.

‘기간 중’과 ‘지금 입장 가능’은 구분한다. 행사 기간에 오늘이 포함돼도 휴관·마감·매진일 수 있다. 예약 재고 연동이 없으면 실제 예약 가능 상태를 확정하지 않는다.

같은 장소의 여러 전시는 별도 행사로 저장한다. 찜·일정에는 행사 식별자를 보관해 행사명·날짜가 사라지지 않도록 한다. 장소 탭에 보여주더라도 시설 찜과 행사 찜은 중복으로 합치지 않는다.

### 데이터 확보 후보

1. 서울시 문화행사 정보: 분류, 자치구, 행사명, 장소, 기간, 이용요금, 홈페이지, 좌표, 시작·종료일, 유무료, 행사시간을 제공한다. 서울 행사 첫 연동 후보.
   - https://data.seoul.go.kr/dataList/OA-15486/S/1/datasetView.do?tab=A
2. 한국관광공사 TourAPI: 축제·공연·행사 등 관광정보 제공. 서울 축제 보강 및 향후 지역 확장 후보.
   - https://api.visitkorea.or.kr/
3. 행사 주최기관·전시장 공식 정보: 공공 데이터에 빠진 휴무·회차·예약 링크 등을 운영자가 보완.

위는 연동 후보이며 모든 민간 전시·팝업의 수록이나 실시간 매진 정보 제공을 보장하지 않는다. 이미지 이용 조건·출처를 확인하고 기존 이미지 정책에 맞게 제공한다.

## AI가 수행할 최소 역할

- 요청에서 지역·날짜·시간·동행·관심사를 추출하고 빠진 조건을 확인한다.
- 해당 날짜에 이용 가능한 검증된 장소·행사를 후보로 고른다.
- 선택한 축제·전시를 고정하고 앞뒤 식사·카페·산책을 연결한다.
- 이동·체류시간과 일정 종료 시각을 맞추고, 교체는 선택한 구간 안에서 제안한다.
- 추천 이유는 실제 반영한 조건으로 설명한다. 행사 날짜·가격·운영시간을 모델이 생성해 채우지 않는다.

예: ‘토요일 오후 전시 보고 밥 먹기’ → 토요일 관람 가능한 전시 선택 → 관람 소요시간 확보 → 주변 식당 → 귀가 시간에 맞는 코스.

## 운영에 필요한 최소 기능

- 행사 수집·갱신 결과와 마지막 성공 시각 확인, 실패 시 재시도.
- 같은 행사의 중복 병합, 시설 매칭, 관리자 수정·비노출·취소 처리.
- 종료 행사 추천 제외, 저장한 과거 여행에는 당시 기록 유지.
- 출처가 삭제·변경되거나 날짜가 불명확한 행사 검토.
- 지역·날짜·위치 권한 미제공, 빈 결과, API 실패와 재시도 처리.
- 실제 영업시간을 모르면 ‘영업중’으로 단정하지 않기.

## 개발 순서 제안

1. PC GNB와 공통 탐색 구조 확정: 장소 / 코스 / 행사 상세 및 행동 연결.
2. 기존 장소 DB로 장소 탐색·상세·찜·여행 담기 흐름 완성.
3. 행사 DB·수집·관리 기능과 축제·전시 목록·상세 구현.
4. 행사 날짜 검증과 기존 AI 추천·여행 편집기 연결.
5. 모바일의 내 여행 이어보기·현장 길찾기·교체 흐름 완성 및 기기 간 점검.
6. 위 흐름 안정화 후 친구 초대·실시간 공동 편집·권한·이력·되돌리기.

최소 출시 판단 기준: 장소 또는 행사를 발견 → 찜 → 여행에 담기 → 빈 구간 AI 추천 → 저장 → 모바일에서 이어서 길찾기까지 한 흐름으로 작동한다.
