# 3일 연속 코스플래닝 호출 제한 수정

한 사용자가 1분 안에 1일차 → 2일차 → 3일차를 추천받는 흐름을 기준으로 수정했습니다.

## 원인과 수정

- 추천 1회가 경로 API 요청 1회는 아닙니다. 최대 3번의 후보 탐색에서 각각 최대 3가지 방문 순서를 조회하므로 최대 9개 요청이 필요합니다. 화면 지도 조회는 별도입니다.
- 기존 경로 제한은 사용자당 분당 12회였고, 같은 요청이 관광정보 전체 분당 30회 제한에도 포함됐습니다.
- 경로 조회는 분당 60회로 조정하고 관광정보 읽기 한도에서 분리했습니다. 관광정보 읽기는 분당 120회입니다. 기타 관광정보 쓰기 요청은 기존 분당 30회입니다.
- 로그인 사용자는 계정별, 비로그인 사용자는 기존 IP 기준을 사용합니다. 전체 API 제한, 하루 유료 API 제한, 경로 엔드포인트 동시 처리 3개 및 공급자 배치 동시 처리 3개는 유지됩니다. 외부 공급자의 자체 한도는 별도입니다.
- 화면 지도에서 HTTP 429를 일반 조회 실패로 숨기지 않고 서버의 제한 안내를 표시합니다. 새 안내 문구는 한국어·영어·중국어·일본어를 지원합니다.

## 배포

1. 백엔드 `routes/tourism/ratePolicy.js` 신규 파일과 수정한 `index.js`, `dayRoute.js`를 함께 배포하고 PM2를 재시작합니다.
2. 프론트 `npm run build` 후 `dist`를 배포합니다.

DB 테이블 변경과 신규 환경변수 설정은 없습니다. 운영 배포는 이 작업에서 실행하지 않았습니다.

## 검증

`node --test tests/tourismRatePolicy.test.js tests/dayRoute.test.js` 7개 통과.

실제 Express 제한 미들웨어와 모의 경로 서비스를 사용해 한 계정의 경로 요청 30회·관광정보 조회 33회가 1분 안에 통과함을 확인했습니다. 설정한 한도를 넘으면 429와 Retry-After가 반환되고, 다른 계정의 한도는 독립적인 것도 확인했습니다. 외부 유료 API 호출은 하지 않았습니다.

프론트 빌드 및 변경 파일 ESLint 통과. 기존 번들 크기 경고는 남아 있습니다.
