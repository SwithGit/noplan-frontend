# 모바일 홈·탐색·찜·마이 구현

작성일: 2026-09-16. 로컬 구현·검증 완료. 운영 배포·Git 커밋·푸시는 하지 않았다.

## 사용자 요청 반영

PC 여행 홈과 여행 편집 화면 디자인은 유지했다. `/app`에서 1024px 미만은 새 모바일 홈, 이상은 기존 PC 여행 홈을 표시한다. 탐색·마이도 각 화면을 별도로 구성했다. 너비를 바꿔도 홈 입력과 PC 여행 생성 입력은 유지되며, 숨겨진 화면의 대화상자가 키보드 조작을 가로채지 않도록 했다.

모바일 하단 메뉴는 **홈 / 탐색 / 찜 / 마이**다. 진행할 코스는 홈의 ‘골라둔 코스’ 카드 또는 추천 결과·탐색·찜에서 다시 열 수 있다.

## 화면

### 홈

1. 출발 동네 선택. 현재 위치는 사용자가 눌러서 요청한다. 위치 권한이 없으면 동네·역을 직접 입력한다.
2. 큰 노피와 ‘오늘, 어디 갈까?’ 제목. 최초 참고 시안의 보라색·캐릭터 중심 디자인으로 조정했다.
3. ‘노피에게 말해줘’ 채팅형 입력과 서비스 지역 안내. 기존 자연어 조건 분석 → 조건 확인 흐름으로 연결한다.
4. ‘빠른 추천 받기’ 버튼형 입력. 기존 질문 흐름으로 연결한다.
5. 원본 시안대로 빠른 추천 버튼 아래, 카테고리 바로 위에 홍보 배너를 표시한다. 화면 맨 위 배치는 잘못된 해석이어서 수정했다. 연보라색 지도·비행기 일러스트 배너이며 ‘내 여행’으로 연결한다.
6. 맛집 / 카페 / 놀거리 / 문화·전시 / 산책·명소 / 술·야간. 선택한 카테고리가 추천 조건에 반영된다.
7. 로그인한 사용자의 선택 지역 주변 장소. 비로그인에는 작은 로그인 안내를 표시한다.
8. 공개 동네 코스 탐색 진입.

홈에 ‘지금 / 10분 뒤’ 시간 칩을 추가하지 않았다. 시간은 추천 질문 안에서 정한다. AI 추천은 기존 서울·도보 범위를 유지한다.

주변 장소는 카탈로그 조회이며 매번 유료 AI·외부 수집을 호출하지 않는다. 좌표가 있으면 주변 약 2km 사각 범위를 조회하고, 직접 입력하면 주소·도로명·가까운 역 이름의 검색어를 사용한다. Local Discoveries는 카탈로그 품질 정책을 통과한 장소를 **별점 내림차순 → 동일 별점이면 후기 수 내림차순 → 동일하면 ID 내림차순**으로 보여준다. SQL에서 개수 제한 전에 정렬하며 별점 미확인(NULL)은 뒤로 배치한다. 카드에도 저장된 별점과 후기 수를 표시하고, 미확인 수치를 0으로 만들지 않는다. 개인 취향 모델이나 실시간 영업중 판정으로 표현하지 않는다. 사진은 기존 소유 이미지 출처 정책(manual/team_upload/merchant_upload/owner_upload)을 따른다. 관리자 제외·비활성·저장된 휴폐업 상태를 제외한다.

### 탐색

- 선택 동네 또는 전체 공개 코스, 수동 동네 선택과 현 위치.
- 코스·장소 검색, 6개 테마 필터.
- ‘좋아요 많은 순’, ‘최신 공개순’. 근거 없는 인기·개인화 문구를 사용하지 않는다.
- 장소 수와 체류시간을 표시하고 이동시간은 별도임을 안내한다. 체류시간 데이터가 없으면 미확인으로 표시한다.
- 코스 상세 → 코스 찜 / 개별 장소 찜 / 지도 검색 / 코스 시작.
- 공개 코스의 좋아요와 개인 찜은 별개다. 하트를 눌러도 공개 좋아요 수는 바뀌지 않는다.

### 찜

- `/app/favorites`: 코스 / 장소 탭, 이름·동네 검색, 최근 저장순.
- 계정별 서버 저장, 재접속·다른 기기에서 같은 목록 조회.
- 홈 주변 장소, 탐색, 추천 결과, 코스 지도, 장소 상세에서 찜 가능.
- 저장 성공 후 표시를 바꾸며, 실패했을 때 저장된 것처럼 표시하지 않는다. 요청 중 중복 클릭을 막는다.
- 찜 목록 로딩 실패와 빈 목록을 구분하고 다시 불러오기를 제공한다.
- 저장 당시 장소 정보를 보관한다. 카탈로그 ID가 있는 장소가 삭제·제외되면 목록 조회 시 상태를 표시하고 해당 코스 시작을 막는다. 모든 외부 장소의 현재 영업·삭제 상태를 실시간 확인하는 기능은 아니다.
- 기존 `saved_courses` 기록은 삭제·이동하지 않았다. ‘이전에 저장한 코스 보기’로 접근할 수 있다. 기존 코스 공개 관리와 새로운 개인 북마크를 분리했다.

### 마이

- 닉네임·프로필, 찜 바로가기.
- 내 여행: 예정 / 여행 중 / 지난 여행, 기기의 작업 초안과 계정 저장 여행. 날짜 분류는 한국 시간 기준.
- 최근 추천받은 코스, 기존 저장 코스·공개 관리 진입.
- 계정 설정·로그아웃·개인정보 처리방침.
- 소셜 로그인 내부 식별자를 새 모바일 프로필에 표시하지 않는다.
- 친구 초대·실시간 협업은 이전 계획대로 별도 후속 단계다.

## API와 데이터

백엔드 `D:/Backend/NoPlan/routes/library/`:

| 요청 | 동작 |
|---|---|
| `GET /api/library/favorites` | 현재 계정 찜 목록 |
| `PUT /api/library/favorites` | 코스·장소 북마크 저장, 같은 항목 중복 방지 |
| `DELETE /api/library/favorites/:id` | 현재 계정의 해당 북마크 해제 |
| `GET /api/library/nearby?area=성수동` | 로그인 후 지역 장소 조회 |
| `GET /api/library/nearby?lat=...&lng=...` | 로그인 후 좌표 주변 장소 조회 |

모든 library API는 서명된 로그인 세션을 요구한다. body의 사용자 ID를 신뢰하지 않는다. 타입·배열 개수·문자 길이·URL 프로토콜·좌표를 검증하며 저장 필드를 명시적으로 제한한다. DB 쿼리는 소유자 조건과 바인딩 파라미터를 사용한다.

기존 `/api/course/explore/explore-courses`에 `sort=latest`를 추가했다. 기존 likes/views 요청은 유지한다.

### 배포

**프론트와 백엔드를 모두 배포해야 한다. 백엔드 먼저 배포한 후 프론트를 배포한다.**

- 신규 테이블 `noplan_favorites`는 첫 찜 API 요청 때 자동 생성한다. 현재 DB 계정의 CREATE 권한이 필요하다.
- 기존 테이블 변경 및 데이터 이전은 없다. 추가 환경변수 없음.
- 주변 장소 API는 기존 `noplan_places`, `noplan_place_images` 카탈로그 스키마를 사용한다.
- 실제 운영 DB 접속이나 테이블 생성은 이번 작업에서 실행하지 않았다.
