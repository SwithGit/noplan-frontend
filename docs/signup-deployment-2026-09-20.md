# 회원가입 화면 및 SENS 인증 적용

PC는 GNB 아래 중앙 카드, 모바일은 노피 소개와 카드로 구성했습니다. 일반 가입은 한 화면에서 끝나며, 소셜 신규 가입은 아이디·비밀번호 없이 추가 정보를 입력합니다. 기존 소셜 회원은 추가 가입을 거치지 않습니다. 소셜에서 받은 이름·이메일·닉네임은 미리 채워집니다.

일반 가입은 아이디 중복 확인, 비밀번호 확인, 이름, 이메일, 닉네임, 휴대폰 인증, 동의를 받습니다. 생년월일은 기존 날짜 형식과 선택 정책을 유지하며 성별도 선택입니다. 여행 스타일은 가입 필수에서 제외했습니다. 이번 작업에는 별도 취향 설정 화면은 포함하지 않았습니다.

## 운영자가 준비할 값

백엔드 환경변수에 다음 값을 설정합니다. 키를 프론트 환경변수나 채팅에 붙이지 마세요.

```dotenv
NCP_ACCESS_KEY=네이버클라우드_Access_Key
NCP_SECRET_KEY=네이버클라우드_Secret_Key
NCP_SENS_SERVICE_ID=SENS_SMS_서비스_ID
NCP_SENS_FROM=SENS에_등록된_발신번호_숫자만
SIGNUP_POLICY_VERSION=확정문서버전
SIGNUP_TERMS_URL=https://확정된-이용약관-주소
SIGNUP_PRIVACY_URL=https://확정된-개인정보-수집이용-동의문-주소
SIGNUP_MARKETING_URL=https://확정된-마케팅-수신동의문-주소
```

기존 `AUTH_TOKEN_SECRET`은 그대로 유지합니다(32자 이상 필요). SENS는 현재 국내 010 번호를 지원합니다. 국제번호 `+82 10...`은 백엔드에서 국내 번호로 정규화합니다. UI는 010 숫자 입력을 받습니다.

서비스 이용약관과 마케팅 문서는 아직 확정되지 않아 작성하거나 실제 동의문처럼 표시하지 않았습니다. 내용 보기 버튼과 HTTPS 문서 연결 설정을 준비했습니다. 기존 `/privacy`는 현 가입 항목·선택 취향 정책과 대조 후 확정해야 합니다. 특히 개인정보처리방침과 수집·이용 동의문은 같은 문서로 임의 간주하지 않습니다.

필수 문서 URL·버전, SENS 설정, 인증 테이블 중 하나라도 준비되지 않으면 신규 가입과 인증문자 발송은 차단합니다. 화면에서는 준비 중 안내를 표시합니다. **이 백엔드를 먼저 배포하면 설정 완료 전까지 기존 가입 화면에서도 신규 가입을 완료할 수 없습니다.** 기존 로그인과 여행 기능은 유지됩니다. 마케팅 URL이 없으면 선택 동의만 비활성화되며 필수 가입에는 영향을 주지 않습니다.

## 적용 순서

1. MySQL Workbench에서 서비스 DB를 선택한 후 백엔드 `sql/20260920_signup_phone.sql`을 열어 전체 실행합니다. 새 테이블 3개만 생성하며 기존 회원 데이터는 수정하지 않습니다. 사용 중인 `users` 테이블은 트랜잭션을 지원하는 InnoDB여야 합니다.
2. 백엔드 변경 파일을 배포하고 위 환경변수를 설정한 다음 `pm2 restart noplan-backend --update-env`로 재시작합니다.
3. 프론트 `npm run build` 후 `dist`를 배포합니다. 일반 가입과 소셜 추가 가입은 함께 배포해야 합니다.
4. 실제 발신번호로 문자 수신, 인증 완료, 일반/소셜 가입, 같은 번호 재가입 차단을 확인합니다. 이 작업에서는 운영 DB·실제 문자·운영 배포를 실행하지 않았습니다.

## 인증 동작

- 무작위 6자리 코드, 3분 만료, 60초 재발송 대기, 코드별 오입력 최대 5회.
- DB에서 번호별 시간당 5회 발송 제한. 코드·번호는 인증 테이블에 HMAC 형태로 저장합니다.
- IP당 시간당 10회, 프로세스당 하루 500회 발송 요청 상한도 적용합니다. 이 두 메모리 상한은 PM2 프로세스 수와 재시작에 영향을 받습니다. 다중 인스턴스로 확장 시 공유 제한 저장소가 필요합니다.
- 인증 성공 후 10분간 가입 가능. 번호 변경·재발송·가입 완료 시 이전 인증으로 가입할 수 없습니다.
- SENS의 202 응답은 발송 접수입니다. 실제 수신은 운영자가 휴대폰에서 확인해야 합니다.
- 일반/소셜 모두 동일한 번호 중복 검사와 DB UNIQUE 제약을 사용합니다. 이미 입력된 기존 회원 번호도 정규화해서 비교하며, 기존 계정에 자동 연결하지 않습니다.
- 계정, 번호 점유, 동의 문서 버전·URL·수신동의·동의 시간을 한 트랜잭션에 저장합니다.
- 인증번호, 비밀번호, SENS 비밀키는 로그에 출력하지 않습니다.
- 장기 미완료 인증 행 정리는 운영 DB에서 만료 시간/발송 제한 기간을 고려하여 수행할 수 있습니다. 회원 탈퇴 구현에서 `signup_phone_claims`, `signup_agreements`의 보유·삭제 정책도 반영해야 합니다.

## 검증

실제 SENS 대신 모의 발송을 사용해 서명·응답 처리, 미설정 차단, 만료·오입력·재발송, 위조 인증, 다른 번호 사용, 일반/소셜 동시 가입, 기존 번호 중복, DB 오류 시 롤백을 테스트합니다. 기존 연령·성별 추천 연계 테스트도 새 가입 계약에 맞춰 유지했습니다.

SENS 구현 참고: [메시지 발송](https://api.ncloud-docs.com/docs/en/sens-sms-send), [API 요청 서명](https://api.ncloud-docs.com/docs/en/common-ncpapi).
