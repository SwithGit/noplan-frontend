# PC 축제·전시 탐색 및 여행 담기 — 2026-09-16

## 완료 범위

- PC GNB: 여행 탐색 / 축제·전시 / 내 여행 / 찜, 우측 여행 만들기 및 마이·로그인.
- `/app/events`: 전국 지역, 기간, 행사명·장소, 축제·전시·공연·행사, 무료 확인 여부, 정렬과 페이지 이동.
- `/app/events/:id`: 포스터, 개최 기간, 관람 시간, 장소, 요금, 대상, 공식 안내 및 지도 링크.
- 기존 여행의 날짜·구간 선택 또는 새 당일 여행 생성 후 행사 담기. 선택한 구간으로 편집기를 연다.
- 행사 ID·개최 기간·관람 시간을 여행 JSON에 보관한다. 같은 날짜의 중복 추가와 개최 기간 밖으로 일정 변경을 막는다.
- 담기는 브라우저 초안 저장이다. 계정 보관은 기존 편집기의 **여행 저장**을 누른다.
- 관람 60분은 조정 가능한 기본 계획값이다. 시간 지정 티켓·휴관·예약 여부를 자동 확정하지 않는다.
- 모바일 홈의 추천 방식, 홍보 배너 순서, 하단 메뉴는 유지했다. 친구 초대·공동 편집은 이번 범위에 없다.

## 데이터 연동

백엔드에서 한국관광공사 TourAPI `KorService2/searchFestival2`, `detailIntro2`, `detailCommon2`와 서울시 `culturalEventInfo`를 호출한다. 인증키는 브라우저로 보내지 않는다.

2026-09-16 실제 조회 확인: TourAPI 종료 전 행사 283건, 서울 문화행사 409건(전시 103건). 제공기관 간 중복 제거 전 숫자이며 데이터는 변경된다. 유형은 제공기관 분류·제목을 바탕으로 정규화한다. 전체 민간 전시·팝업의 완전한 목록을 의미하지 않는다.

목록은 제공기관별 전체 수집에 성공했을 때만 MySQL 스냅샷을 교체한다. 제목·기간·위치가 같은 항목만 보수적으로 중복 제거한다. 이전 수집본이 24시간 이상 지났으면 다음 요청 때 갱신하며, 실패 시 이전 데이터와 갱신 안내를 제공한다. 실패 재시도 간격은 10분이다. 별도 정기 실행 작업은 없다.

상세 조회 실패 시 확보된 기본 정보를 표시한다. 공식 포스터는 외부 URL로 표시하며 로딩 중·실패 시 대체 일러스트를 표시한다. 종료·취소된 행사는 목록과 담기에서 제외한다. 이미 여행에 담은 행사의 기간은 당시의 스냅샷이며 이후 변경·취소를 자동 동기화하지 않는다.

## 배포

**프론트와 백엔드를 함께 배포한다. 백엔드를 먼저 반영한다.** 이전 백엔드는 여행 저장 시 새 행사 메타데이터를 유지하지 않는다.

백엔드 운영 환경에 다음 설정을 반영하고 재시작한다.

```dotenv
PUBLIC_DATA_SERVICE_KEY=발급받은_TourAPI_일반인증키
SEOUL_OPEN_DATA_KEY=서울_열린데이터광장_인증키
SEOUL_EVENTS_ALLOW_HTTP=true
```

TourAPI 키는 인코딩·디코딩 형태를 모두 처리하며 같은 환경변수를 중복 선언하지 않는다. 서울시 공식 `http://openapi.seoul.go.kr:8088` 조회는 사용자의 명시적 허용을 받아 활성화했다. 운영 서버에서도 해당 외부 연결이 가능해야 한다. 이 설정들은 `VITE_` 변수로 만들지 않는다.

첫 행사 API 요청에서 `noplan_event_catalog` 테이블을 자동 생성한다. 현재 백엔드 DB 계정에 CREATE/SELECT/INSERT/UPDATE 권한이 있으면 Workbench에서 직접 쿼리를 실행할 필요는 없다. 기존 여행 테이블 구조는 변경하지 않는다. 자동 생성 권한이 없는 환경에서는 아래 테이블을 먼저 생성한다.

```sql
CREATE TABLE IF NOT EXISTS noplan_event_catalog (
  provider VARCHAR(20) PRIMARY KEY,
  document JSON NOT NULL,
  fetched_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

첫 수집은 평소 목록 조회보다 오래 걸릴 수 있다. 배포 후 `/api/events` 성공 응답과 `/app/events` 목록·상세를 확인한다.

## 검증 및 한계

- 백엔드 전체 테스트 257개 통과: 키 정규화, 날짜·URL 검증, 수집 실패 시 이전 자료 유지, 검색 조건, 여행 행사 데이터 보존·기간 검증 포함.
- 프론트 프로덕션 빌드와 변경 파일 ESLint 통과. 번들 500 kB 초과 경고는 남아 있다.
- Edge 브라우저: 지역·날짜·무료 필터, 상세, 새 여행 담기·저장·새로고침, 기존 여행 선택·중복 방지, 빈 결과·오류·재시도 확인.
- PC 1024/1440/1920px 가로 넘침 및 모바일 390px 홈 메뉴·배너 순서 확인.
- 공식 API와 포스터는 실제 연결로 확인했다. 브라우저 검증의 계정·DB 저장은 테스트 응답과 실제 여행 검증 함수를 사용했다. 운영 DB에 직접 테이블 생성·여행 저장을 실행하지 않았으며 배포도 하지 않았다.

백엔드 `node scripts/probe-event-apis.js`는 인증키를 출력하지 않고 연결 상태를 확인한다. `node scripts/preview-event-catalog.js`는 공개 목록 전체를 조회하고 건수·예시만 출력하며 DB를 변경하지 않는다.
