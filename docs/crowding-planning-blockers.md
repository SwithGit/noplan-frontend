# NoPlan 혼잡도 기능: 기획·외부 준비 필요사항

- 작성일: 2026-08-08
- 대상: 기획 페이지 전달용
- 기준 문서: `docs/crowding-integration-plan.md`
- 목적: 현재 개발자가 구현하거나 검증할 수 없는 항목과 기획 결정이 필요한 항목을 정리한다.

## 1. 서울시 Open API 인증키 필요

현재 `SEOUL_OPEN_DATA_KEY`가 없다.

인증키가 없어도 다음 작업은 가능하다.

- 서울시 혼잡도 Provider 인터페이스 구현
- 응답 정규화 코드 구현
- 캐시와 stale fallback 구현
- Mock 응답 기반 자동 테스트 작성
- 프론트 혼잡도 UI 구현

하지만 다음 작업은 인증키가 있어야 완료할 수 있다.

- 실제 서울시 API 연결 성공 확인
- 운영 환경의 응답 속도와 timeout 확인
- 장소 코드별 실제 데이터 제공 여부 확인
- 실제 응답 필드와 예상 스키마 일치 여부 확인

필요한 준비:

- 서울 열린데이터광장 API 인증키 발급
- 실시간 인구 API 사용 가능 상태 확인
- 운영 서버 환경변수 `SEOUL_OPEN_DATA_KEY` 등록
- 인증키는 프론트나 문서, Git 저장소에 기록하지 않음

## 2. 네 개 권역의 실제 API 응답 샘플 필요

다음 권역을 실제로 호출한 JSON 응답을 최소 한 건씩 확보해야 한다.

| 장소 코드 | 예상 장소명 |
|---|---|
| `POI073` | 연남동 |
| `POI055` | 홍대입구역(2호선) |
| `POI053` | 합정역 |
| `POI007` | 홍대 관광특구 |

확인할 내용:

- 위 장소 코드가 현재 API에서도 유효한지
- 요청 시 코드와 장소명 중 무엇을 사용하는지
- 실제 응답의 `AREA_CD`, `AREA_NM`, 혼잡 단계, 기준 시각 필드명
- 한글 장소명이 정확히 어떤 표기로 등록되어 있는지
- 데이터가 없는 시간대의 응답 형태
- 인증 실패, 잘못된 장소, 호출 한도 초과 시 오류 형태

실제 응답을 받기 전에는 예상 스키마와 Mock 응답을 기준으로만 개발할 수 있다.

## 3. 공식 혼잡 권역 경계 자료 필요

NoPlan 장소의 좌표를 `연남동`, `홍대입구역`, `합정역`, `홍대 관광특구` 중 하나로 정확하게 분류하려면 서울시가 제공하는 공식 Polygon 또는 권역 경계 자료가 필요하다.

필요한 자료:

- 공식 영역 파일 다운로드 주소
- 파일명과 자료 버전
- GeoJSON, SHP 등 파일 형식
- 좌표계
- 각 장소 코드별 Polygon 포함 여부

경계 자료가 없을 때 사용할 수 있는 임시 매핑은 다음과 같다.

| 주소 또는 역 정보 | 임시 매핑 |
|---|---|
| 연남동 | `POI073` |
| 동교동, 홍대입구역 | `POI055` |
| 합정동, 합정역 | `POI053` |
| 나머지 홍대 서비스 권역 | `POI007` |

임시 매핑은 행정동 및 주소 문자열 기반이므로 실제 서울시 혼잡 권역과 정확히 일치한다고 보장할 수 없다.

기획 결정 필요:

- 1차 MVP에서 주소 기반 임시 매핑을 허용할지
- 공식 경계 자료 확보 후에만 좌표 기반 자동 매핑을 적용할지

## 4. 합정역 포함 여부 확정 필요

현재 NoPlan 첫 화면 안내 문구는 다음과 같다.

> 현재 서비스는 홍대입구·연남동 주변 지역에서 이용할 수 있어요.

하지만 혼잡도 기획에는 `POI053 합정역`이 포함되어 있다.

다음 중 하나를 확정해야 한다.

1. 합정역 주변도 실제 추천 서비스 범위에 포함한다.
2. 합정역 혼잡도 연동만 준비하고 현재 사용자 추천 범위에서는 제외한다.
3. 합정역을 포함하도록 첫 화면의 서비스 지역 안내 문구를 변경한다.

서비스 범위가 확정되지 않으면 합정역 데이터를 추천 점수에 반영할지 결정할 수 없다.

## 5. 서울시 데이터의 기능적 한계

서울시 실시간 인구데이터는 매장 단위 데이터가 아니라 권역 단위 데이터다.

따라서 같은 `POI073 연남동`에 포함된 카페와 식당은 모두 동일한 주변 혼잡도를 받는다.

서울시 데이터로 가능한 것:

- 연남동과 홍대입구역 후보의 주변 혼잡도 비교
- 홍대입구역과 합정역 후보의 주변 혼잡도 비교
- 결과 화면에 현재 권역의 주변 혼잡도 표시

서울시 데이터만으로 불가능한 것:

- 같은 연남동 안에서 덜 붐비는 카페 판별
- 특정 매장 내부의 대기 인원이나 좌석 점유율 판별
- 동일 권역에 있는 두 매장의 혼잡도 차이 판별

따라서 사용자에게는 반드시 `매장 혼잡도`가 아니라 `주변 혼잡도`라고 표시해야 한다.

## 6. SKT/TMAP 연동에 필요한 외부 준비

현재 다음 정보가 없어 SKT/TMAP 4차 기능의 실제 개발 완료 및 검증은 불가능하다.

- SK Open API 계정
- 애플리케이션 등록
- 장소 혼잡도 또는 TMAP Puzzle 상품 신청
- API 키
- 계정에 실제 적용된 무료 호출 한도
- 지원 장소 및 상권 목록 응답
- 대표 장소의 실시간 혼잡도 응답 샘플

외부 준비 전 가능한 작업:

- 공통 Provider 인터페이스 정의
- SKT Provider용 빈 어댑터 및 feature flag 준비
- Mock 응답 기반 fallback 테스트

외부 준비 전 불가능한 작업:

- 홍대 및 연남동 데이터 제공 여부 확정
- NoPlan 승인 장소와 SK 지원 장소의 실제 매칭률 산출
- 실제 호출 차감량 확인
- 갱신 주기와 응답 속도 측정
- 예상 월 비용 계산
- 유료 전환 여부 판단

## 7. 출처 표기 문구 확정 필요

프론트 결과 화면에서 사용할 최종 출처 문구를 확정해야 한다.

임시 후보:

- `서울시 실시간 인구 데이터 기반 추정치`
- `서울시 실시간 도시데이터 제공`

기획 및 정책 담당자가 공공데이터 출처표시 조건을 확인하고 최종 문구를 정해야 한다.

사용자 화면에는 다음 내용이 드러나야 한다.

- 권역 기반 주변 혼잡도라는 점
- 기준 시각
- 데이터 출처
- stale 데이터라면 최근 확인 정보라는 점
- 실제 매장 내부 인원수나 좌석 현황이 아니라는 점

## 8. 혼잡도 추천 점수표 수정 필요

현재 NoPlan 추천 엔진은 점수가 낮은 후보를 우선한다.

따라서 기존 기획서처럼 붐빔 상태에 음수 점수를 적용하면 붐비는 장소가 오히려 우선될 수 있다. 혼잡할수록 양수 페널티를 더해야 한다.

권장 초기값:

| 혼잡 단계 | `대기 적게` 미선택 | `대기 적게` 선택 |
|---|---:|---:|
| 여유 | 0 | 0 |
| 보통 | 0 | +200 |
| 약간 붐빔 | 0 | +600 |
| 붐빔 | 0 | +1,000 |
| 정보 없음 | 0 | 0 |

추가 원칙:

- stale 데이터는 위 페널티의 50%만 적용한다.
- 모든 후보가 같은 권역이면 동일한 페널티가 적용되므로 기존 순서를 유지한다.
- 혼잡도 때문에 후보를 제외하지 않는다.
- 핵심 목적, 영업 여부, 필수 슬롯 유지가 혼잡도보다 우선한다.
- 실제 MVP 결과를 보고 환경변수로 수치를 조정할 수 있어야 한다.

## 9. 현재 개발 가능한 범위

아래 작업은 기획 및 외부 준비를 기다리지 않고 개발할 수 있다.

- MySQL 혼잡 권역 컬럼의 안전한 마이그레이션
- 공통 `CrowdingSnapshot` 모델
- 서울시 Provider 인터페이스
- 예상 응답 및 Mock 기반 정규화 로직
- 5분 캐시와 30분 stale fallback
- timeout 및 장애 격리
- API 키가 없거나 기능이 비활성화된 경우 `unknown` 처리
- 코스 결과와 교체 후보에 혼잡도 필드 추가
- 프론트 주변 혼잡도 표시
- `대기 적게`를 구조화된 boolean 값으로 백엔드에 전달
- 혼잡도 소프트 페널티 적용
- API 장애 시 기존 추천 유지
- Mock 기반 백엔드 자동 테스트
- 프론트 TypeScript 빌드 및 렌더링 검증

단, 실제 서울시 API 연동 완료 판정은 인증키와 실제 응답 샘플을 확보한 뒤에만 가능하다.

## 10. 기획 페이지 확인 요청

다음 항목에 대한 답변 또는 자료가 필요하다.

- [ ] 서울시 Open API 인증키 발급 담당자와 일정
- [ ] 네 개 권역의 실제 JSON 응답 샘플
- [ ] 공식 권역 Polygon 또는 영역 파일
- [ ] Polygon이 없을 경우 주소 기반 임시 매핑 허용 여부
- [ ] 합정역을 현재 서비스 범위에 포함할지
- [ ] 서울시 데이터의 최종 출처 표기 문구
- [ ] 혼잡도 점수표를 양수 페널티 방식으로 변경 승인
- [ ] SK Open API 계정 및 상품 신청 담당자
- [ ] SKT/TMAP 실제 무료 호출 한도 확인 결과
