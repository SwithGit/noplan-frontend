# DB 우선·실시간 주변 검색 보완

2026-09-18 · 공모전 마감 2026-09-21 16:00 KST

## 사용자가 확정한 방식

코스를 구성하는 공통 엔진을 유지하고 후보 장소의 공급 경로를 바꾼다. 현재 위치 주변에 승인된 DB 장소가 있으면 그 자료를 사용하고, 없으면 카카오 Local API로 주변 가게를 검색한다. 실시간 후보를 가게 카탈로그에 수집·승인·적재하지 않는다. 이후 해당 지역에 승인 장소가 들어오면 다음 추천 요청부터 DB를 사용한다.

사용자가 추가로 선택한 정책: **가격 미확인 후보도 추천하되 예산 검증 완료라고 표시하지 않는다.** 가격을 임의로 만들거나 사용자의 예산을 0원/무제한으로 바꾸지 않는다.

## 구현 범위

- DB 조회의 서울 전용 region_key 조건을 제거하고 출발 좌표 반경으로 조회한다. 요청 범위는 기존 도보 검색 반경을 유지한다.
- 반경 안의 승인·활성 추천 장소가 하나라도 있으면 DB 경로를 사용한다. 일부 업종이 부족하거나 예산·취향에서 탈락했다는 이유로 실시간 검색을 호출하지 않는다.
- 해당 반경에 DB 후보가 없을 때만 필요한 활동 유형을 카카오로 검색한다. 최대 8개 쿼리, 동시 2개, 쿼리당 15개 결과, 자동 재시도·추가 페이지 없음.
- 실시간 장소에 `candidateSource: live`, 공급자 ID, 카카오맵 링크를 보존한다. 메뉴·평점·리뷰를 생성하거나 DB 검증 표식을 붙이지 않는다.
- 업종은 검색어가 아닌 제공된 업종 분류로 판단한다. 문화시설·스터디카페·공유사무실·편의점 등 부적합 후보를 제외하고, 운영자가 비활성화한 동일 이름·인근 좌표의 장소도 재등장시키지 않는다.
- 기존 필수 활동·시간·체류·도보·저녁·술자리·자동 채움 로직을 공유한다. 영업시간은 기존 외부 조회로 확인하며, 확인된 휴무·폐업·체류 중 영업 종료는 제외한다.
- 실시간 후보의 Google 조회는 매장 일치·영업·방문 가능 정보에 사용한다. Google 평점으로 기존 카카오·네이버 검증을 통과했다고 표시하지 않는다.
- 메뉴 가격이 없는 실시간 후보에 한해 가격 미확인을 허용한다. 계산 가능한 비용에는 기존 예산 제한을 적용하고, 모르는 비용이 포함되면 전체 최소·최대·평균을 `null`, `costKnown=false`로 반환한다.
- 가격 미확인을 예산 부족의 증거로 삼아 무료 산책을 추가하지 않는다.
- PC 구간 추천과 공통 조건 화면의 서울 전용 차단을 해제한다. 국내 좌표 범위는 서버가 확인한다. 차량·대중교통 추천 확장을 의미하지 않는다.
- 결과에 실시간 검색·품질 확인 필요·총예산 미확인을 안내한다. 저장 코스와 여행에 담은 장소에도 실시간 출처·가격 확인 필요 상태를 보존한다.

가게 카탈로그 자동 저장과 기존 사용자의 코스/여행 저장은 별개다. 기존 검색 코스 기록과 사용자가 적용·저장하는 여행 기능은 유지된다.

## 오류와 제한

- 카탈로그 DB 장애는 빈 데이터로 취급하지 않는다. DB 조회 실패와 카카오 검색 실패·429 한도 초과를 각각 안내한다.
- 실시간 검색은 가격·리뷰·메뉴를 보장하지 않는다. 메뉴 근거가 필요한 구체적인 술 종류·저녁 반주·음식 제외 조건은 여전히 후보 부족으로 끝날 수 있다.
- 실시간 가게는 DB ID가 없으므로 기존 개별 장소 교체 API를 사용하지 않는다. 화면에서 조건 수정 후 코스 재추천을 안내한다. DB 코스 교체는 유지한다.
- 국내 검색 가능 범위와 실제 추천 성공 범위는 다르다. 주변 장소·시간·경로 조건에 맞는 코스가 없으면 실패 사유를 반환한다.
- 실제 도보 검증은 기존 TMAP 설정·한도를 따른다. 추정 경로는 추정으로 표시하고, 강제 최대 도보 거리 조건을 추정으로 통과시키지 않는다.

## 실행 설정

- 백엔드의 기존 `KAKAO_REST_API_KEY`를 사용한다. 키는 프론트에 전달하지 않는다.
- `COURSE_LIVE_FALLBACK_ENABLED=false`로 실시간 보완을 끌 수 있다. 기본은 사용이다.
- 현대 `/generate-course` 경로는 DB 우선이다. `NOPLAN_MVP_CATALOG_ONLY`를 전체 해제해서 과거 실시간 조합 방식을 복원할 필요가 없다.
- 신규 DB 테이블·마이그레이션은 없다. 기존 가게·여행 저장소를 사용한다.

## 검증

- 백엔드 전체 테스트 508개 통과.
- 프론트 테스트 6개 통과, TypeScript·프로덕션 빌드 통과. 기존 500kB 초과 번들 경고는 남아 있음.
- 변경 파일의 `git diff --check` 통과. 운영 배포·운영 DB 변경 없음.

실제 카카오 API를 사용한 읽기 전용 확인에서 경주 황리단길 주변 후보 27곳(식당 6·카페 21), 울산 태화강국가정원 주변 후보 13곳(식당 11·카페 2)을 확인했다. 당시 식당·카페 쿼리와 1.5km 반경의 결과이며 전수 목록이나 승인 가게 수가 아니다. DB 적재는 하지 않았다.

자동화 검증은 실제 요청 핸들러→DB/실시간 공급자 선택→공통 엔진→응답을 연결한다. 외부 공급자·DB 대역으로 지방 추천, 이후 DB 적재 시 자동 전환, 예산 정책, 제거 장소, DB 장애, 한도 초과와 기존 서울 회귀를 확인한다. 실제 카카오 후보 검색 확인과 실제 Google/TMAP/운영 DB를 모두 연결한 최종 코스 검증은 구분한다.
