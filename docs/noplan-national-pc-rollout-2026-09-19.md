# PC 전국 관광지·코스플래닝 연결 — 2026-09-19

전국 관광공사 자료를 PC의 장소 선택, 인기순·맞춤 추천순·이름순, 노피의 코스플래닝, 일정 사진에 연결했다. DB 스키마 변경 없이 백엔드 공개 데이터 스냅샷을 사용한다. 운영 배포는 수행하지 않았다.

## 적용 범위

- 여행 만들기의 목적지를 그대로 검색·자동 추천 범위로 사용한다. 예: 경주, 부산 해운대구, 경기도 수원, 제주도, 제주시, 강원 고성, 경남 고성.
- 시·군·구를 지정하면 해당 범위를 유지하고, 시·도를 지정하면 그 안의 구역을 플래너에서 선택한다. 고성·중구·광주처럼 동명이 있는 입력은 시·도를 함께 입력하도록 안내한다.
- 관광지, 문화시설, 레포츠, 여행코스, 쇼핑, 음식점을 검색한다. 축제와 숙박은 이 선택 목록에 추가하지 않았다. 묶음 여행코스는 자동 추천의 단일 방문 노드로 사용하지 않는다.
- 관광공사 공식 분류 FD01/02/03은 식사, FD05는 카페로 분류한다. 이름·메뉴로 판단하던 울산 보조 로직도 유지한다. 카페 체류시간은 최소 30분이다.
- 자동 코스는 실제 경로 기준 장소 사이 도보 1km·차량 7km 제한을 유지한다. 부족하면 장소 수를 줄이거나 부족 안내를 표시하며 거리 제한을 자동으로 늘리지 않는다. 대중교통 자동 추천은 기존처럼 미지원이다.
- 큰 지역의 후보 탐색을 공간 격자로 바꾸고, 필요한 식당·카페가 거리 제한 안에 함께 있는 시작 후보부터 탐색한다. 다른 날짜의 중복 장소 제외, 노드 변경, 일정 반영, 공동 편집 충돌 보호를 유지한다.
- 일정 사진은 담긴 공식 장소 ID만 조회한다. 개인화 추천 결과 전체를 사진용 공용 캐시에 넣지 않는다.
- PC 검색 로그에 `destination`을 남기고 지역별 자동 추천 진단을 지원한다.

## 데이터와 연결 기준

2026-09-19 수집 결과: 관광공사 전체 응답 49,679행 중 지원 분류·국내 좌표·주소 지역이 확인된 자료와 기존 울산 자료를 합쳐 **44,831개** 공식 장소를 사용한다. 사진 URL이 있는 장소는 **39,216개**다. 지역 주소가 확인되지 않은 909행은 지역별 목록에서 제외했다. 표본은 주소·지역 코드가 비어 있는 묶음 여행코스였으며 좌표만으로 시·군·구를 추측하지 않았다.

데이터랩 기간은 사용자가 확인한 **2025-09~2026-08**이다. 전국 성·연령 7,228행 및 검색순위 7,885관측을 정규화한 파일을 사용한다. 기존 울산 구별 통계는 전국 파일보다 상세하므로 우선 보존했다.

- 실제 서비스 장소 기준 성·연령 자료 연결: **5,841개**.
- 실제 서비스 장소 기준 검색건수 연결: **3,373개**.
- 장소 수와 통계 연결 수는 다르다. 통계가 없는 장소를 0건·방문비중 0%로 표시하지 않는다. 결과 전체에 통계가 없으면 인기순 또는 이름순으로 대체한 이유를 안내한다.
- 같은 시·도 및 시·군·구 안에서 정규화 이름이 유일한 경우만 연결한다. 공백·지역 접두어·지역 괄호 표기·유네스코 세계유산 표기를 정리한다. 예: `경주 불국사 [유네스코 세계유산]` ↔ `불국사`. `불국사밀면`처럼 이름 일부만 같은 곳은 연결하지 않는다.
- 행정구역 중복 관측의 검색건수를 합산하거나 임의로 큰 값만 선택하지 않는다. 동명 TourAPI 장소가 둘 이상이면 연결을 보류한다.
- 제주특별시, 재물포구, 시+구 표기 차이를 처리한다. 전남광주통합특별시 원자료는 주소의 구·군을 기준으로 기존 광주/전남 검색 범위에 연결하며 전체 통합 명칭도 검색할 수 있다. 원본 CSV는 변경하지 않았다.

## API

백엔드 루트: `D:/Backend/NoPlan`.

- `GET /api/tourism/search?destination=경주&type=all&sort=popular&page=1`
- `GET /api/tourism/nopi-catalog?destination=부산&profile=member`
- `GET /api/tourism/regions`
- `GET /api/tourism/photos?ids=126166,126207` — 최대 100개, 공개 사진 필드만 응답.

회원 추천은 기존 인증된 회원의 생년월일·성별을 사용한다. 개인화 응답은 `private, no-store`이며 생년월일·회원 ID를 반환하지 않는다. 기존 `region=ulsan` 및 목적지 없는 기존 키워드 검색 API도 호환된다.

## 배포에 필요한 파일

프론트만 배포하면 새 API와 데이터가 없어 전국 검색이 작동하지 않는다. **백엔드와 스냅샷을 먼저 반영·재시작한 뒤 프론트를 배포한다.**

백엔드 신규 런타임 파일:

- `routes/tourism/national.js`
- `routes/tourism/nationalRegions.js`
- `data/tourism/national-tourapi.json` (약 22MB)
- `data/tourism/national-datalab.json` (약 5.5MB)

백엔드 변경 파일: `routes/tourism/router.js`, `routes/tourism/ulsan.js`, `middleware/pcDiagnostics.js`. 기존 `ulsan-*.json`도 계속 필요하다. 수집·검증 스크립트 및 테스트도 저장소에 함께 보관한다. 데이터랩 상세 감사 보고서는 런타임 필수 파일은 아니다.

TourAPI 목록을 갱신할 때 백엔드 루트에서 `node scripts/fetch-national-tourism.cjs`를 실행한다. 기존 `PUBLIC_DATA_SERVICE_KEY`를 사용하며 전체 페이지 확인 후 임시 파일을 교체한다. 실행마다 약 50회 공개 목록 API 호출이 발생한다. 갱신 후 백엔드 재시작이 필요하다. 전국 CSV 갱신은 `scripts/import-national-datalab.py`와 기존 준비 문서를 참고한다.

기존 관광공사·카카오·TMAP 키를 사용한다. 새 유료 API 계약이나 추가 DB 마이그레이션은 도입하지 않았다.

## 남은 데이터 한계

전국 모든 가게를 확보한 것은 아니다. 지역별로 관광공사 등록 장소 및 통계 연결 비율이 다르다. 가까운 식당·카페가 부족한 권역은 직접 장소 검색으로 보완할 수 있다.

전국 운영시간·휴무일을 전부 사전 수집하지 않았다. 기존 울산의 수집된 운영 정보만 자동 일정 검증에 반영하며, 전국 장소 상세는 관광공사 상세 API에서 조회할 수 있다. 미확인 운영시간과 가격은 확인이 필요하다고 안내한다. 휴무·영업시간까지 전국 자동 추천에 엄격히 적용하려면 후속으로 선택 후보의 상세 정보를 캐시하는 단계가 필요하다.
