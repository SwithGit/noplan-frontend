# NoPlan PC·모바일 관광 서비스 기획안 v0.2

작성일: 2026-09-16. 상태: 검토용 제안, 구현·배포 계획 확정 전.

최신 결정(2026-09-16): 공동 편집·초대·권한·변경 이력·되돌리기는 다른 핵심 기능 완성 이후로 연기한다. 모바일 홍보 배너는 원본 시안대로 빠른 추천 버튼 아래·카테고리 위이며 화면 맨 위가 아니다. 아래 초기안과 충돌하면 이 결정과 `noplan-minimum-service-scope-2026-09-16.md`를 우선한다. 신규 GNB·콘텐츠 범위는 아직 검토용 제안이다.

사용자 피드백 반영: PC 방향 승인. 모바일 홈의 시간 칩 제거, 홍보 배너 상단 유지, 채팅형·버튼 선택형 추천 진입을 각각 유지. 탐색·찜·마이·공통 방향 승인.

## 1. 서비스 정의

**미리 함께 짜는 여행부터, 지금 떠나는 동네 여행까지.**

NoPlan은 목적지·시간·이동 조건에 맞춰 관광 일정을 만들고, 여행 중에도 주변 경험을 연결하는 AI 여행 서비스다. 식당·카페는 여행의 구성 요소이며, 관광지·산책·문화·지역 경험과 이어지는 일정이 대표 상품이다.

- PC의 첫 과업: 여행을 만들고 친구와 전체 일정을 함께 편집한다.
- 모바일의 첫 과업: 지금 또는 잠시 뒤 시작할 짧은 여행을 추천받고 실행한다.
- 같은 계정의 여행·장소·코스·찜을 공유한다. 기기마다 첫 화면과 편집 밀도를 달리한다.
- PC에서도 즉시 추천, 모바일에서도 여행 생성·초대 수락·일정 편집이 가능하게 한다. 기기를 이유로 핵심 과업을 막지 않는다.

## 2. 사용자 요구와 기획상 가정

확정 요구: 관광 중심, PC의 미래 여행·교통수단·당일/숙박 일정, 친구 초대와 실시간 공동 편집, 큰 일정 안에서 기존 추천 활용, 모바일 즉시 추천, 하단 홈/탐색/찜/마이.

기획상 가정:

1. '성산 일출봉 가기'는 꼭 갈 기준 장소와 그 주변을 묶는 일정 구간으로 해석한다.
2. 아침/점심/저녁은 시작용 틀이다. 실제 일정은 오전/점심/오후/저녁·야간 등 시간 범위를 자유롭게 늘리거나 합칠 수 있다.
3. 첫 버전은 일정 계획과 안내에 집중한다. 항공·숙박 결제와 예약 중개는 포함하지 않는 제안이다. 사용자가 예약 정보를 직접 입력하고 외부 예약 페이지를 여는 것은 별도 고려한다.
4. 관광 포지셔닝은 전국 확장 방향이다. 현재 검증된 서울 추천 범위를 제주 등 전국으로 이미 확대했다고 간주하지 않는다.
5. PC의 '몇 시간 뒤'는 기본 제안값이다. 동일 날짜·가까운 출발 시각을 강제로 차단하지 않는다.

## 3. 여행 정보 구조

여행 → 날짜 → 일정 구간 → 방문 장소.

- 여행: 제목, 목적지, 시작/종료 날짜, 출발·귀가 조건, 동행, 교통, 숙소, 멤버.
- 날짜: 그날의 시작/종료 지점과 시간, 하루 예산·이동 강도.
- 일정 구간: 시간 범위, 지역/주제, 기준 장소, 앞뒤 연결 지점, 선택 조건.
- 방문 장소: 도착/출발 시각, 체류시간, 이동, 메모, 비용 정보, 고정 여부.
- 짧은 코스: 순서가 있는 장소 묶음. 단독으로 추천·찜할 수도 있고 일정 구간 안으로 가져올 수도 있다.

예시(실제 이동 가능성을 검증한 일정이 아님): 제주 2박 3일 → 2일차 → 오전 '성산 주변' → 고정한 성산 일출봉 + 주변 식사 + 카페.

구간에는 기준 장소가 없어도 된다. '오후에는 실내에서 2시간'처럼 조건만 넣고 AI로 채울 수 있다. 반대로 관광지 하나만 남겨도 완성된 구간으로 취급한다.

기존 추천과 연결할 때는 시작 위치뿐 아니라 종료 제한 시간, 다음 구간 도착 지점, 반드시 유지할 장소·예약도 함께 반영해야 한다. 독립 코스를 단순히 이어 붙이면 시간과 동선이 맞지 않는다.

## 4. PC 정보 구조와 화면

상단 전역 메뉴: 여행 만들기 / 여행 탐색 / 내 여행 / 찜 / 프로필.

### P1. 시작 화면

- 대표 문구: '다음 여행, 큰 일정부터 함께 정해요.'
- 첫 행동: 목적지 + 날짜 또는 '날짜 미정' → 여행 만들기.
- 이어서 편집할 여행, 초대받은 여행, 테마별 여행 예시.
- 즉시 추천은 보조 진입으로 제공.
- 관광 콘텐츠는 도시·지역·테마 중심으로 보여준다. 음식점 목록이 첫 화면의 대부분을 차지하지 않게 한다.

### P2. 여행 생성

입력을 3단계로 나누되 선택 항목은 나중에 추가할 수 있다.

1. 어디·언제: 목적지, 당일/숙박, 날짜, 출발·귀가 시각. 날짜 선택으로 몇 박 며칠을 계산한다.
2. 어떻게: 출발지 → 목적지 이동(기차/버스/항공/자가용 등)과 현지 이동(도보/대중교통/렌터카 등)을 분리한다. 도착지부터 시작하거나 아직 미정일 수도 있다.
3. 무엇을: 동행, 꼭 갈 곳, 예산·걷기 선호, 숙소(선택).

'AI로 큰 일정 만들기'와 '직접 시작하기'를 제공한다. 모든 장소를 정해야 다음으로 갈 수 있는 방식은 피한다.

### P3. 공동 여행 편집기 — PC 핵심 화면

- 상단: 여행명, 날짜·교통, 접속 중인 멤버, 친구 초대, 저장 상태.
- 좌측: 날짜 목록, 미배치 장소함, 숙소·교통 정보.
- 중앙: 선택한 날짜의 일정 구간을 세로 배치. 요약에는 주제, 시간 범위, 기준 장소, 장소 수, 이동 부담을 표시한다.
- 우측: 지도와 선택 구간의 상세 정보. AI 추천은 구간 선택 시 문맥에 맞게 연다.
- 좁은 PC 화면은 지도/상세를 전환하도록 하며, 일정·지도·AI 채팅 3개를 늘 항상 펼쳐두지 않는다.

주요 행동: 구간 추가, 순서 이동, 날짜 간 이동, 구간 복제, 기준 장소 고정, 구간 추천받기, 장소 직접 추가, 댓글·제안.

일정 밖에 담아둘 '후보 장소함'이 필요하다. 친구가 장소를 발견했다고 즉시 확정 일정에 넣도록 강제하지 않는다.

### P4. 일정 구간 상세 / AI 코스 채우기

1. 구간 선택: '오전 · 성산 주변'.
2. 조건 확인: 시작 위치·시각, 끝낼 시각·다음 장소, 교통, 동행, 예산, 고정 장소.
3. 기존 노플랜 방식으로 목적·소분류를 선택하거나 자연어로 요청한다.
4. 추천안은 2~3개 이내로 비교한다. 대표 차이는 이동·시간·예산·분위기다.
5. 전체 구간 교체 또는 특정 장소 교체의 변경 전후를 확인한다.
6. '이 구간에 적용'하면 팀원 화면에 반영된다. 나머지 일정은 유지한다.

고정한 장소와 예약 시각은 유지한다. 맞지 않으면 '장소를 줄이기 / 구간 시간을 늘리기 / 다른 후보 보기' 중 선택하게 한다. 다음 예약을 놓치게 하는 변경을 조용히 적용하지 않는다.

### P5. 여행 요약 / 공유

- 날짜별 핵심 장소, 구간별 시간, 교통, 숙소, 미정 항목.
- 모바일에서 열기, 멤버 초대 관리, 보기 전용 공유.
- 링크 공개 여부와 편집 권한은 별도다. 팀 여행은 기본 비공개를 제안한다.

## 5. 공동 편집 동작

첫 버전에서도 필요한 최소 협업:

- 소유자/편집자/보기 전용 권한, 초대 링크와 철회.
- 초대 수락 후 같은 여행을 편집한다. '팀 플래닝'을 별도 제품이나 메뉴로 만들지 않는다.
- 장소 추가·제거, 순서와 시간 변경의 실시간 반영, 작업 중인 구간과 변경자 표시.
- 동시에 같은 구간을 바꾸면 상대 변경을 덮어쓰지 않도록 충돌 안내와 재확인.
- AI 제안은 적용 전까지 개인 미리보기이며 적용할 때 공유 일정이 바뀐다.
- AI 미리보기 이후 다른 멤버가 해당 구간을 바꾸면 최신 일정 기준으로 다시 검토한다.
- 되돌리기와 변경 이력. 여행 삭제·멤버 권한 변경은 소유자 중심.
- 연결 끊김/저장 중/저장 실패를 구분하고 실패한 편집의 재시도를 제공한다.

후순위: 실시간 채팅, 후보 투표, 세부 비용 정산. 초기에는 장소 메모·구간 댓글로 의견을 남길 수 있다.

## 6. 모바일 정보 구조

하단 고정 메뉴는 홈 / 탐색 / 찜 / 마이.

| 메뉴 | 대표 과업 | 담을 내용 |
|---|---|---|
| 홈 | 두 방식으로 코스 추천 시작 | 현재/선택 지역, 상단 홍보 배너, 채팅 입력, 버튼 선택형 빠른 추천, 카테고리, 로그인 개인화 |
| 탐색 | 다른 여행 발견 | 주변·선택 지역의 공개 코스, 테마, 검색, 지도/목록 |
| 찜 | 나중에 갈 것 보관 | 찜한 코스·장소, 지역 필터, 여행에 담기 |
| 마이 | 내 여행과 계정 관리 | 진행/예정/지난 여행, 초대, 최근 기록, 취향·설정 |

'찜한 코스'와 '내 여행'을 구분한다. 찜은 발견한 콘텐츠의 북마크, 내 여행은 내가 만들거나 참여해 편집하는 일정이다. 찜한 코스를 내 여행으로 가져오면 개인·팀 일정의 복사본으로 취급한다.

### M1. 홈

사용자 피드백을 반영한 세로 순서:

1. 현재 지역/직접 지역 선택 + 필요한 경우 알림.
2. 홍보 배너. 추천 진입·카테고리보다 위에 유지한다.
3. 대표 문구와 노피: '오늘, 어디 갈까?'
4. 채팅형: '노피에게 말해보세요' 자유 입력과 전송. 원하는 조건을 직접 설명하는 사용자용.
5. 버튼 선택형: '빠른 추천 받기' + '입력 없이, 몇 번의 선택으로'. 기존 단계형 질문으로 진입한다.
6. 카테고리 6개: 맛집, 카페, 놀거리, 문화·전시, 산책·명소, 술·야간. 선택 시 코스 추천 조건에 반영한다. 단일 장소 탐색은 별도 '장소만 보기'로 구분한다.
7. 로그인 상태에서 '지금 내 주변 추천 장소'. 위치 제공 또는 직접 선택한 지역이 있어야 한다.
8. 선택 지역의 짧은 테마 여행/큐레이션 코스.

홈에는 '지금/10분 뒤/직접 설정' 시간 선택을 두지 않는다. 추천 진입 후 기존 질문에서 시각과 이용 시간을 받는다. 채팅에서 시간이 명시된 경우 추출 내용을 확인하고 불필요하게 다시 묻지 않는다. 두 추천 진입은 입력 선호에 따라 구분하되 조건 확인·결과·저장 체계는 공유한다.

비로그인은 일반 추천과 공개 탐색을 사용할 수 있다. 개인화 섹션에는 작고 명확한 로그인 안내를 배치하며, 큰 흐림 영역으로 첫 화면을 차지하지 않는다. 로그인과 위치 권한은 별개이며 위치 거절 시 역·동네를 직접 고른다.

여행 당일에는 상단에 '오늘의 여행 이어보기'를 추가한다. 기존 추천 진입도 유지하고 시작 위치를 현재 위치/계획상 위치 중 선택할 수 있게 한다.

### M2. 빠른 추천 입력

기존 질문을 짧게 묶는다.

- 출발 위치는 홈의 선택 지역을 초기값으로 활용한다. 출발 날짜·시각은 추천 질문 안에서 받는다.
- 필수 결정: 언제까지 또는 몇 시간, 누구와, 무엇을 하고 싶은지.
- 이동·예산·분위기는 요약된 기본값으로 보여주고 필요할 때 펼친다.
- 자연어 요청에서 추출한 위치·시간·목적을 확인 칩으로 보여준다. 모호하거나 빠진 필수 조건만 다시 묻는다.
- 앞으로 일정이 있다면 '다음 약속 전까지'를 종료 조건으로 가져올 수 있다.

### M3. 추천 결과 / 여행 시작

- 첫 추천 1개를 펼쳐 보여주고 대안 1~2개는 접어둔다.
- 총 시간, 장소 수, 총 이동, 시작/종료 시각, 예상 비용 범위(근거가 있을 때)를 우선 표시한다.
- 장소 순서와 이동 시간을 함께 보여준다. 지도/목록을 전환한다.
- '왜 이 코스인가요?'에는 실제 반영한 조건을 짧게 설명한다.
- 각 장소: 교체 / 찜 / 상세. 코스: 시작 / 찜 / 내 여행에 담기.
- 시간·영업 정보가 불확실하면 확인 시점이나 확인 필요 상태를 표시한다. 영업중과 방문 예정 시각의 영업 가능성을 구분한다.

### M4. 탐색

- 처음에는 현재 또는 선택 지역을 사용하며, 국내 다른 지역을 직접 탐색할 수 있다.
- 코스 검색, 시간·동행·테마·이동 부담 필터. 처음에는 필요한 필터만 노출한다.
- 카드에는 사진, 지역·제목, 소요시간, 장소 수, 이동, 특징을 표시한다.
- '인기순'과 '조회순'을 동시에 앞에 두기보다 추천순/인기순/최신순을 사용한다.
- 인기는 실제 저장·이용 등 집계 기준과 기간을 정한 뒤 제공한다. 초기 데이터가 부족하면 '추천 코스' 또는 '에디터 선정'으로 표기한다.
- 공개 코스 상세 → 내 조건으로 맞추기 → 미리보기 → 시작/내 여행에 담기.
- 남이 작성한 코스가 미래 방문 시각에도 유효한지 다시 검증한다.

### M5. 찜

- 코스 / 장소 두 탭. '매장'보다 관광지까지 포괄하는 '장소' 명칭.
- 기본 최신 저장순, 지역·유형 필터. 지역별 그룹은 선택적으로 제공한다.
- 장소 여러 개 선택 → 이 장소로 코스 만들기 / 내 여행에 담기.
- 코스 → 내 조건으로 맞추기 / 내 여행에 담기.
- 사라지거나 추천에서 제외된 장소는 상태를 알리고 대체 후보를 안내한다.

### M6. 마이

- 닉네임과 프로필. 소셜 로그인 내부 ID를 노출하지 않는다.
- 내 여행: 진행 중 / 예정 / 지난 여행, 초대받은 여행.
- 최근 본 코스, 선호 교통·예산·걷기·동행 정보, 계정 설정.
- 찜 목록을 다시 길게 나열하지 않고 바로가기만 둔다.
- 친구 초대는 특정 여행의 '함께 계획하기'에서 실행한다.

### M7. 여행 중 화면

- 지금 갈 장소, 다음 이동, 남은 일정, 길찾기.
- '1시간 비었어요', '덜 걷고 싶어요', '이 장소 바꾸기' 같은 상황별 변경.
- 지나간 일정과 고정 예약을 유지하고 남은 구간만 재추천.
- 팀 여행에서는 적용 전 영향 범위를 보여주고 변경을 실시간 공유한다.
- 실시간 위치 공유는 일정 협업과 별도 기능이며 첫 버전에 자동 포함하지 않는다.

## 7. 첨부 모바일 시안에 대한 피드백

유지할 점: 보라색 브랜드, 노피 캐릭터, 지역 선택, 한눈에 보는 카테고리, 코스 카드, 장소/코스 저장 구분.

바꿀 점:

1. 채팅 입력과 버튼 선택형 빠른 추천을 각각 유지한다. '말해서 추천받기'와 '입력 없이 고르기'로 차이를 명확하게 설명한다.
2. 홍보 배너는 추천 진입과 카테고리 위에 유지한다. 배너 아래에 두 추천 방식을 배치하고 홈 시간 선택은 제거한다.
3. 하단 '코스'는 요청대로 '찜'으로 바꾼다. 내가 만든 여행은 마이에 둔다.
4. 햄버거 메뉴에 하단 메뉴와 같은 항목을 중복 배치하지 않는다. 공통 설정은 마이로 모은다.
5. 탐색 카드에 시간·이동 부담을 추가한다. 감성 태그만으로는 당장 시작할 수 있는지 판단하기 어렵다.
6. 마이의 저장 목록은 찜과 중복되지 않도록 내 여행 중심으로 바꾼다.
7. 한 화면에서 지역 표기를 일치시킨다. 울산 위치와 서울 한정 안내가 동시에 보이는 상태는 제공 범위를 혼동시킨다.
8. '2곳'인데 카테고리 합계가 5곳인 식의 수량 불일치를 없앤다.
9. 캐릭터는 시작·로딩·빈 상태·도움말에 집중한다. 카드 정보와 행동 버튼의 공간을 먼저 확보한다.
10. 보라색은 대표 행동과 선택 상태에 집중하고 장소 사진과 정보는 담백한 배경에 배치한다. 흐림·그라데이션 면적을 줄인다.

## 8. AI의 역할과 신뢰

PC: 큰 일정 초안 → 선택 구간 채우기 → 시간·동선 재조정.
모바일: 지금 가능한 코스 → 조건에 맞는 장소 교체 → 여행 중 남은 시간 재구성.

채팅형과 버튼 선택형 진입을 모두 제공한다. 사용자가 원하는 입력 방식을 고르게 하고, 조건 확인과 추천 결과는 동일한 정책을 따른다. 여행 편집 화면에서는 '이 구간 채우기' 같은 행동 버튼으로 AI를 호출한다.

- 기본적으로 검증 가능한 장소를 사용한다. 존재하지 않는 장소·운영시간·교통편·예약 가능성을 생성하지 않는다.
- '예약됨', '예상', '미확인'을 구분한다. 가격 정보가 없으면 임의 금액을 제시하지 않는다.
- 사용자가 직접 선택한 소분류와 고정 장소를 존중한다.
- 왜 추천했는지, 무엇이 바뀌는지, 시간에 맞지 않는 이유를 보여준다.
- 일정을 줄여야 하면 무리하게 채우기보다 적은 장소로 구성한다.
- 화면 예시의 시간·장소·멤버는 기획용 샘플이다. 실시간 추천·공동 편집 구현을 의미하지 않는다.

## 9. 운영 범위와 기존 기능 재사용

인수인계 기준으로 재사용 가능한 자산: 서울 장소 카탈로그, 목적·동행·시간·도보 조건 추천, 영업 검증, 공통 제외 정책, 관리자 검수, 리뷰 기반 적합도, 인증 기반 기능.

추가 설계·확인이 필요한 영역: 다일 여행과 일정 구간, 시작/종료 제약과 기준 장소 유지, 여행 멤버·권한, 실시간 편집·충돌·이력, 코스 공개와 인기 집계, 전국 관광 데이터, 교통수단별 시간 계산.

- 제주 사례는 구조 설명이다. 초기 출시는 서울 도심 여행으로 범위를 명확히 하는 방안을 권장한다.
- 지원하지 않는 지역도 수동 계획은 허용할 수 있으나 AI 추천 가능 지역과 구분해야 한다.
- 현재 도보 추천을 차량·대중교통 추천에 그대로 사용하지 않는다.
- 예약 시간, 이동 버퍼, 관광지 체류시간, 숙소와 귀환을 고려해야 숙박 여행으로 확장할 수 있다.
- 문화/전시의 activity+detail_type 분리, hotplace 산책 정책, 관리자 제거 장소의 재활성화 방지를 유지한다.

## 10. 권장 개발 순서

1차: 모바일 홈/탐색/찜/마이 정리, 기존 추천 진입과 결과·시작 흐름 개선, 서울 관광 콘텐츠 표현. PC 여행/날짜/구간 정보 구조도 함께 확정한다.

2차: PC 여행 생성과 구간 편집, 기존 추천을 구간에 넣기, 고정 장소와 다음 일정 제약. 모바일에서 같은 여행 열기·수정하기.

3차: 친구 초대, 역할, 실시간 편집, 충돌 방지, 변경 이력. 이 단계까지 완료해야 요청한 PC 공동 여행 기능의 최소 버전이 완성된다.

4차: 타 지역 데이터·교통 모드 확장, 비용·날씨·예약 맥락, 후보 투표 등. 데이터 준비와 검증 범위에 따라 나눈다.

관찰할 지표: 첫 추천 결과까지의 시간, 추천 후 코스 시작 비율, 장소 교체율과 이유, 여행 초안 완성률, 초대 수락/공동 편집률, PC 여행의 모바일 이어보기 비율. 목표 숫자는 현재 이용 데이터를 확인한 뒤 정한다.

## 11. 같은 /app 주소에서 PC·모바일 화면 제공

- 진입 주소는 `https://noplan.live/app`로 유지한다. 별도 모바일 도메인을 만들 필요가 없다.
- 화면 너비에 따라 PC용 여행 작업 화면과 모바일용 추천 화면을 선택한다. 레이아웃은 CSS로 대응하고 주요 화면의 정보 구조가 다르면 컴포넌트를 분리한다.
- 초기 제안 기준: 768px 미만 모바일, 768~1023px 태블릿, 1024px 이상 PC. 이는 기기 판정값이 아닌 레이아웃 검증 시작점이며 실제 콘텐츠에 맞춰 조정한다.
- 태블릿은 2열 구성, PC는 일정·지도/상세를 함께 표시한다. 모바일은 한 번에 한 과업과 하단 내비게이션을 중심으로 한다.
- 브라우저의 기기명만으로 분기하지 않는다. 창 크기 변경, 태블릿 회전, 터치·마우스·키보드 입력에 대응한다.
- 로그인·권한·API·여행 ID·저장 상태는 공유한다. 창 크기 변경으로 작성 내용이나 선택 여행이 초기화되지 않게 한다.
- 여행 상세 링크는 기기에 맞는 표현으로 같은 여행을 연다. PC 여행을 모바일에서 이어보고 모바일 추천을 PC 여행에 담을 수 있게 설계한다.
- PC 화면은 넓은 일정 보드, 날짜 탐색, 지도, 드래그 편집 중심. 드래그의 키보드·버튼 대안도 제공한다.
- 모바일 화면은 보라색 브랜드와 노피, 상단 홍보 배너, 채팅·선택형 추천, 터치하기 쉬운 카드와 하단 메뉴 중심.
- 공통 색상·글꼴·아이콘·버튼·간격 규칙을 먼저 정해 두 화면의 브랜드를 통일한다.

현재 소스 확인: `App.tsx`의 `/app`은 `PlannerHome`으로 연결되며 `AppFrame.tsx`는 공통 `phone-frame`을 사용한다. 모바일 중심 프레임을 기기별 화면 구조로 나누는 작업이 필요하다. 현재 홈에도 자유 입력과 버튼 선택형 추천이 분리되어 있으므로 그 의도를 유지한다. 여행 계층과 실시간 협업은 별도 기능 구현 범위다.

## 12. 다음 상세 기획에서 결정할 항목

- 첫 관광 확장 지역과 해당 지역의 데이터 확보 범위.
- 1차 출시에서 당일/숙박 여행 지원 범위.
- 교통수단별 실제 지원 순서와 예약 정보 입력 범위.
- 공개 코스의 초기 공급 방식(운영자 큐레이션/사용자 공개)과 집계 기준.
