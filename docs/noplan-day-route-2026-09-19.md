# 하루 동선 보기

일정의 날짜 제목 옆 `하루 동선 보기`에서 선택한 하루를 넓은 카카오 지도와 시간대별 카드로 확인한다. 지도는 각 구간의 중심 관광지(없으면 첫 장소)에 순서 번호를 표시하며, 점선은 방문 순서 안내이지 실제 도로 경로가 아니다. 지도 번호를 누르면 해당 카드로 이동한다.

## 편집 및 반영

- 위·아래 버튼은 시간대와 구간 ID/제목을 유지하며 장소 묶음, 지역, 메모를 교환한다. 중심 관광지와 주변 카페 등 모든 장소를 함께 옮긴다. 기존 이동·대기 시간은 무효화한다.
- `장소 교체`는 기존 관광지 선택창을 열어 상세정보를 확인하고 변경한다. 다른 날짜와 구간은 보존하며, 같은 날 중복 관광지는 기존 검증으로 막는다.
- 순서, 관광지, 이동수단 변경은 모달 안의 작업본에서만 진행한다. `변경한 동선 반영`을 눌러야 기존 일정과 저장 흐름에 반영한다. 이동수단 변경은 여행 전체에 적용한다고 안내한다.
- 닫기/ESC로 미반영 편집을 버릴 때 확인한다. 일정 반영은 기존 되돌리기로 한 번에 복구할 수 있다. 모달이 열려 있는 동안 기존 공동 편집 동기화를 일시 보류하고, 반영 시 기준 문서가 달라지면 덮어쓰지 않는다.

## 이동시간

`POST /api/tourism/day-route`에 이동수단과 최대 11개 구간 사이 좌표 쌍을 보낸다. 운영 DB를 변경하지 않는다.

- 출발은 앞 구간의 마지막 장소, 도착은 다음 구간의 첫 장소이다. 주변 장소가 있어도 중심 관광지에서 출발했다고 가정하지 않는다.
- 자동차는 기존 카카오 모빌리티 경로 서비스(주차 여유 5분 포함), 도보는 기존 TMAP/Google 도보 서비스를 재사용한다. 현재 조회한 경로이며 미래 방문일의 교통 예측은 아니다.
- 앞 구간 종료 시각부터 다음 구간 시작까지 이동 여유를 계산한다. 이미 담긴 일정이 종료 시각을 넘으면 그 초과도 차감한다. 미확인 구간 내 이동은 기존 15분 임시값을 사용한다.
- 이동시간이 여유를 넘으면 부족한 시간을 표시한다. 구간 내 체류/이동 초과도 별도 안내한다. 경로를 못 구하거나 좌표가 없으면 확인 필요로 표시하며, 성공한 다른 구간은 유지한다.
- 대중교통은 아직 소요시간 API가 없어 자동 계산하지 않고 카카오맵 길찾기로 연결한다.
- 서버는 좌표/이동수단/중복 ID/최대 구간 수 검증, 사용자·IP별 요청 제한, 요청 동시성 제한, 외부 서비스 3개 단위 조회 및 기존 서비스 캐시를 적용한다. 운영 서버의 기존 일일 유료 API 한도에도 포함한다.

## 검증과 미리보기

- 프론트 모델 4개: 시간대 보존, 장소/메모/고정 상태 보존, 빈 시간대 이동, 경계 처리, 주변 장소 기준 출발, 시간 초과, 좌표 누락.
- 백엔드 5개: 잘못된 요청, 도보/자동차 분리, 부분 실패, 미지원 대중교통, 동일 위치, 키 미설정, HTTP 응답과 외부 조회 동시성.
- 실제 브라우저에서 울산 3곳 지도 표시, 자동차/도보 조회, 부족한 시간 표시, 지도→카드 이동, 순서 변경, 관광지 교체, 기존 일정 반영, 되돌리기 확인.
- 관련 회귀 테스트 포함 프론트 17개·백엔드 24개 통과. 변경 파일 ESLint, 백엔드 구문 검사, 프론트 프로덕션 빌드 통과.
- 지도 SDK에 등록된 `http://localhost:5173/dev-preview/day-route.html`에서 확인한다. `127.0.0.1:5198`은 지도 제공기관의 등록 도메인이 아니어서 SDK가 401을 반환한다. 운영 지도 설정은 변경하지 않았다.
- 미리보기는 `dev-preview/day-route.tsx`의 샘플 여행이며 운영 계정에 저장하지 않는다. 로컬 브라우저 초안은 기존 저장 흐름을 사용한다. 관광지 검색은 20대 여성 샘플 회원, 경로는 실제 외부 API 응답이다.

```powershell
# 백엔드: D:/Backend/NoPlan
node scripts/preview-ulsan-tourism.cjs
# 프론트: D:/VSCode/NoPlan/noplan-web
$env:VITE_APP_API_URL='http://127.0.0.1:4318'
npm run dev -- --host localhost --port 5173 --strictPort
```

## 배포

프론트 빌드와 백엔드 `routes/tourism/dayRoute.js`, `routes/tourism/router.js`, `server.js`를 함께 반영하고 백엔드를 재시작한다. 기존 경로 API 키 설정을 재사용한다. DB 스키마 변경은 없다. `scripts/preview-ulsan-tourism.cjs` 변경은 로컬 미리보기용이다. `PlaceMapAdmin.tsx`의 타입 변환 한 줄은 새 지도 SDK 타입 선언과 기존 관리자 지도 타입의 충돌만 해소하며 실행 동작은 동일하다.

운영 배포는 수행하지 않았다. 주변 코스 생성 알고리즘은 이번 작업 범위에서 변경하지 않았다.
