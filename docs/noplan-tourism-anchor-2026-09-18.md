# PC 중심 관광지 일정 추가 — 2026-09-18

## 사용 흐름

1. PC 홈에서 목적지와 여행 날짜를 입력한다.
2. `관광지부터 고르기`에서 관광지 이름 또는 지역명을 검색한다. 예: `첨성대`, `태화강`.
3. 결과의 주소를 확인하고 관광지와 예상 관람시간을 선택한다.
4. 홈에서 방문 날짜와 오전·오후·저녁 구간을 고른 뒤 `여행 만들기`를 누른다.
5. 선택한 구간에 중심 관광지가 첫 번째 고정 장소로 들어간다. 다른 구간에서도 `중심 관광지 담기`로 추가할 수 있다.
6. 해당 구간의 `이 구간 추천받기`는 관광지 관람 후 남은 시간과 마지막 장소 좌표를 기존 도보 코스 알고리즘에 전달한다. 기존 소주제 장소가 있으면 그 마지막 장소부터 이어 붙인다.

관광지·관람시간 변경, 중심 관광지 제거, 되돌리기, 브라우저 초안 보관 및 로그인 계정 저장을 지원한다. 관광지를 교체할 때 기존 소주제 장소를 지우지 않는다. 이동과 운영시간은 사용자가 다시 확인해야 한다.

## 데이터와 구현

- `GET /api/tourism/search?keyword=첨성대&type=12&page=1`
- 서버의 기존 `PUBLIC_DATA_SERVICE_KEY`로 한국관광공사 `KorService2/searchKeyword2` 조회. 키를 브라우저로 보내지 않는다.
- 관광지(12), 문화시설(14), 레포츠(28)를 선택해서 검색. 전국 키워드 검색이며 주소 기반 도시 필터나 인기순 순위는 아니다. 한국관광100선 인증 표시는 하지 않는다.
- 한 페이지 20건, 최대 5페이지. 좌표 없는 항목·유형이 다른 항목 제외. 오류와 빈 결과 구분.
- 검색 캐시 10분·최대 150개, 동일 요청 병합, 외부 요청 동시 20개 제한, 요청 제한 분당 30회, 제공기관 타임아웃 12초.
- 관광지 원본 전체를 카탈로그 DB에 적재하지 않는다. 선택한 이름·주소·좌표·관람시간·TourAPI ID를 여행 문서에 보존한다. 기존 여행 저장 테이블을 쓰므로 추가 DB 스키마 변경이 없다.
- `TripPlace.source = tourism`, `tourism = {contentId, contentTypeId}`, `fixed = true`, `priceNeedsCheck = true`.
- 한 구간의 중심 관광지는 한 곳이며 첫 장소로 유지한다. 동일 날짜 다른 구간의 동일 관광지 추가, 장소 수 초과, 관람시간+기존 장소+이동 여유의 구간 초과를 추가/변경 시 차단한다.
- 관광지 입장료와 운영시간을 조회·검증한 것으로 표시하지 않는다. 관람시간 기본값은 사용자 조정용이며 제공기관의 권장시간이 아니다.
- 기존 DB 우선 → DB 후보가 없으면 Kakao 실시간 검색 → 공통 코스 생성 흐름을 그대로 사용한다. 이번 기능은 사용자가 중심 관광지를 선택하는 단계이며 여러 관광지의 자동 배분·차량 동선 최적화는 포함하지 않는다.

## 배포

백엔드 관광지 라우트와 여행 저장 검증 변경을 먼저 반영하고 프론트엔드를 배포한다. 프론트만 배포하면 관광지 검색/계정 저장이 지원되지 않는다. 이 작업에서는 로컬 구현·검증만 했으며 운영 서버를 배포하거나 운영 DB에 쓰지 않았다.

## 검증

- 프론트 Node 테스트 9개 통과, TypeScript/Vite 빌드 통과. 기존 500KB 초과 번들 경고는 남아 있다.
- 백엔드 전체 테스트 513개 통과. 공식 검색 정규화/캐시/오류/HTTP 쿼리 검증 및 여행 저장·재조회에서 관광지 정보 보존 확인.
- 기존 실제 키로 `첨성대` 1건, `태화강` 5건(태화강 국가정원 포함), `경주` 첫 페이지 20건 및 다음 페이지 여부 확인.
- 브라우저에서 실제 첨성대 검색 → 오후 구간에 담기 → 관광지와 주소 표시 → 90분에서 60분 변경 시 추천 시작 14:45에서 14:15로 변경 확인.
- 새로고침 보존, 300분 입력 시 구간 초과 차단, 중심 관광지 제거와 되돌리기 확인.
- 다른 날짜/구간의 독립성은 모델 테스트로 확인. 내장 테스트 브라우저의 기본 달력 팝업이 종료되어 다일 여행의 달력 클릭 검증은 완료하지 못했다.
- 이번 화면 검증은 실제 TourAPI를 연결한 임시 로컬 API로 진행했다. 운영 계정/DB 및 Google·TMAP을 포함한 소주제 코스 생성 전체 실연은 별도 확인이 필요하다.

공식 API 안내: https://www.data.go.kr/data/15101578/openapi.do
