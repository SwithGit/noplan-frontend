# 노피 코스 거리 제한 및 이동수단 유지

2026-09-19 변경. 기존 자동 코스의 거리 정책을 아래 기준으로 대체한다.

## 사용자 동작

- 홈에서 도보 / 자가용·렌터카 / 대중교통을 큰 선택 카드로 고른다. 여행 만들기 직전 선택값과 거리 기준을 다시 보여준다.
- 여행에 저장한 이동수단을 노피 코스플래닝이 그대로 사용한다. 변경이 필요할 때만 `이동수단 변경`을 연다.
- 별도로 바꾼 날짜만 날짜별 이동수단을 저장한다. 기본값과 같으면 중복 저장하지 않아 여행 기본값을 따른다.
- 대중교통을 도보로 바꾸지 않는다. 대중교통 자동 추천은 비활성화하고 직접 편집을 제공한다.

## 자동 추천 기준

- 인접한 장소 사이 **실제 조회 경로 거리**가 도보 1,000m, 차량 7,000m 이하인 코스만 자동 생성한다. 전체 하루 이동거리의 합계 제한은 아니다.
- 후보끼리의 직선거리도 동일한 상한 안에 있어야 한다. 가까운 장소가 모인 권역을 우선하고, 높은 인기 점수 때문에 외딴 장소로 이탈하지 않게 한다.
- 관광·쇼핑·카페 순서를 고정하지 않는다. 식사 시간, 운영시간, 체류시간, 종료 시각 조건을 유지하면서 순서를 탐색한다.
- 선정된 최대 6개 장소의 출발점은 유지하고, 최대 3개 순서를 실제 경로로 비교해 총 이동거리가 짧은 순서를 선택한다. 전역 최적 경로를 보장하는 알고리즘은 아니다.
- 초과 구간은 재탐색에서 제외한다. 자동으로 범위를 늘리지 않는다. 가까운 후보가 적으면 장소 수를 줄이고 안내하며, 구성 자체가 불가능하면 사유를 표시한다.
- 경로 조회 실패 시 거리를 추정해서 통과시키지 않고 기존 코스를 유지한다.
- 직접 담은 장소와 기존 저장 일정은 임의로 삭제하지 않는다. 기준을 넘는 구간은 코스 편집 화면에서 안내한다. 새 기준으로 구성하려면 `새 코스 추천받기`를 사용한다.

## 구현 및 배포

- 프론트엔드 변경이며 신규 API 키나 백엔드 배포는 필요 없다. 현재 연결된 도보·차량 경로 API를 사용한다.
- 생성 1회에 최대 3번 후보 재탐색 × 최대 3개 순서를 비교한다. 같은 방향·좌표의 경로는 생성 작업 안에서 재사용한다.
- `coursePolicy.ts`: 거리 상한 및 날짜별 이동수단 상속.
- `nopiModel.ts`: 가까운 후보 묶음 / 방문 순서 탐색.
- `nopiRouting.ts`: 실제 경로 상한 검증 / 경로 비교 / 부족 안내.

## 확인 결과

- 빌드 성공. 관련 테스트 32개 통과. 수정 파일 ESLint 오류 없음(TripWorkspace의 기존 불필요한 eslint-disable 경고 1건).
- 1.4km 도보 및 12.4km 차량 경로가 직선거리 조건을 통과해도 실제 경로 검증에서 거절되는 회귀 테스트 통과.
- 외딴 인기 장소 제외, 백화점을 지나쳤다 카페에서 되돌아가는 순서 개선, 후보 부족 시 축소 안내, 이동수단 저장/상속 테스트 통과.
- 울산 실데이터 브라우저 확인: 도보 코스 구간 210 / 305 / 65 / 60m, 차량 코스 구간 794 / 262 / 280 / 246m. 조회 시점·추천 조건에 따라 결과는 달라진다.
- 홈에서 도보로 만든 여행의 플래너가 도보를 유지함을 확인. 날짜별 차량 변경을 일정에 반영한 후 재진입해도 차량 설정이 유지됨을 확인.
