# NoPlan 비홈 화면 UX/UI 개편 개발 전달서

- 작성일: 2026-08-09
- 대상 프로젝트: `D:\VSCode\NoPlan\noplan-web`
- 개발 범위: 검색 진입 이후 화면, 탐색, 코스, 마이, 해당 화면의 공통 UI
- 명시적 제외: 홈 화면 구조와 기능

## 최신 사용자 피드백 우선 적용

아래 내용은 이 문서의 초기 제안보다 우선한다.

1. 현재 구현된 탐색 화면은 사용자가 승인했으므로 추가 개편하지 않는다. 코스·마이 수정으로 인한 회귀만 확인한다.
2. 사용자 화면에서 `활성 코스`라는 표현을 사용하지 않는다. 코스가 생기는 행동을 명확히 안내한다.
3. 로그인 후 마이페이지는 여러 섹션을 세로로 이어 붙이지 않고 기존 `저장 / 최근 / 방문` 탭 구조로 되돌린다.

## 1. 이 문서를 개발 페이지에 전달할 때의 요청

아래 요구사항을 현재 프론트엔드 코드 기준으로 구현한다. 기획 문구만 정리하는 작업이 아니라 실제 화면, 상태 처리, 인터랙션과 반응형 스타일을 함께 수정해야 한다.

이번 작업에서는 홈 화면 구조를 유지한다. `PlannerHome`의 JSX, 홈의 검색창, 빠른 추천, 퀘스트, 추천 카드의 구성과 동작을 변경하지 않는다. 홈과 같은 파일에 있는 다른 검색 화면은 수정할 수 있지만 홈 코드가 함께 변경되지 않도록 주의한다.

## 2. 제품 내 각 메뉴의 역할

각 탭은 다음 역할이 화면에서 명확히 구분되어야 한다.

| 메뉴 | 역할 |
|---|---|
| 홈 | 새로운 추천 검색의 시작점. 이번 개편 대상 아님 |
| 탐색 | 홍대 권역의 공개 코스를 구경하고 미리 본 뒤 내 코스로 선택하는 곳 |
| 코스 | 현재 선택한 코스를 실제로 확인하고 따라가는 곳 |
| 마이 | 저장한 코스, 최근 본 코스와 계정을 관리하는 곳 |

검색은 홈에서 시작하지만 `/planner/chat` 이후의 입력, 확인, 검색 중, 결과 화면은 이번 개편 대상이다.

## 5. 공통 디자인 규칙

### 5.1 디자인 방향

새 Nopi 캐릭터의 부드러운 흰색·라벤더·네이비 분위기와 어울리는 디자인을 사용한다. 현재 화면의 강한 파란색, 별도의 보라색, 진한 남색 말풍선이 서로 다른 서비스처럼 보이지 않도록 정리한다.

이번 범위의 비홈 화면에 다음 토큰을 사용할 수 있도록 CSS 변수를 추가한다.

```css
--nopi-bg: #f8f7fb;
--nopi-surface: #ffffff;
--nopi-surface-soft: #f1efff;
--nopi-primary: #5b5ce2;
--nopi-primary-pressed: #4849c9;
--nopi-ink: #19213a;
--nopi-text: #242b3b;
--nopi-muted: #70788b;
--nopi-border: #e7e6ee;
--nopi-success: #168a67;
--nopi-warning: #c77616;
--nopi-danger: #cf4d5b;
```

홈 전용 셀렉터에는 위 토큰을 강제로 적용하지 않는다.

### 5.2 시각 규칙

- 화면 기본 배경: `--nopi-bg`
- 일반 카드: 흰색, 1px 경계선, 16px 모서리
- 핵심 결과 또는 큰 패널: 20px 모서리
- 버튼: 주요 행동 하나만 채운 색상 사용
- 보조 행동: 흰색＋경계선 또는 텍스트 버튼
- 그림자: 큰 카드에만 약하게 사용하며 여러 겹의 강한 그림자를 제거
- 본문을 전부 굵게 처리하지 않는다.
- 제목, 값, 본문, 보조 문구의 굵기 차이를 명확히 한다.
- 화면 좌우 기본 여백은 모바일 기준 16px 또는 20px 중 기존 쉘과 맞는 하나로 통일한다.
- 터치 대상 최소 높이는 44px로 한다.
- 아이콘은 같은 굵기의 선형 스타일로 통일한다.
- 실제 장소를 보여주는 카드에서는 캐릭터보다 장소 사진을 우선한다.

### 5.3 권장 타이포 계층

| 용도 | 크기 | 굵기 |
|---|---:|---:|
| 화면 제목 | 26~28px | 800 |
| 섹션 제목 | 20~22px | 800 |
| 카드 제목 | 16~18px | 750 |
| 본문 | 14~15px | 500~600 |
| 보조 정보 | 12~13px | 500~600 |

기존 `font-weight: 900`, `950`의 과도한 사용은 화면 제목 또는 매우 중요한 숫자를 제외하고 줄인다.

### 5.4 Nopi 사용 규칙

- 작은 말풍선과 채팅 아바타에는 `src/assets/nopi/nopi-icon.png`를 사용한다.
- 캐릭터는 인사, 검색 중, 검색 완료, 빈 상태처럼 감정 전달이 필요한 곳에만 사용한다.
- 장소 사진이 필요한 자리를 Nopi 또는 `PlaceVisual` 기본 아이콘으로 대신하지 않는다.
- 같은 화면에 Nopi를 두 번 이상 반복 노출하지 않는다.
- 이미지 자체에 문구가 들어간 `nopi_01~32.png`는 80px 미만 영역에 넣지 않는다.

## 6. 검색 진입 이후 UX 개편

### 6.1 `/planner/chat`: 한 번에 하나씩 선택하는 5단계 화면

현재는 진행률이 `0 / 5`인데 다섯 질문이 한 화면에 모두 노출된다. 이를 동일 경로 안에서 진행되는 단계형 화면으로 변경한다.

별도의 라우트를 다섯 개 만들지 않고 `ChatStart` 내부의 `activeStep` 상태로 관리한다.

#### 상단

```text
[뒤로]  노피와 코스 찾기
        2 / 5
[진행률 표시]
```

- 기존 `Nopi 와 대화중`은 `노피와 코스 찾기`로 수정한다.
- 진행률은 현재 단계가 분명하게 보이도록 한다.
- 첫 단계에서 뒤로가기는 홈으로 돌아간다.
- 2단계 이상에서 뒤로가기는 이전 질문으로 이동하며 선택값을 보존한다.

#### 1단계: 출발 위치

- 현재 위치로 시작
- 주소 직접 입력
- 현재 위치 실패 시 같은 화면에서 홍대 권역 바로 선택 제공
  - 홍대입구
  - 연남동
  - 상수
  - 합정
- 서비스 범위 밖 주소가 입력되면 검색을 진행하지 않고 홍대 권역만 지원한다는 안내와 권역 선택 버튼을 보여준다.

#### 2단계: 출발 시간

- 지금
- 오늘 저녁
- 오늘 밤
- 날짜/시간 직접 선택
- 하나를 선택하면 다음 버튼을 활성화한다.

#### 3단계: 동행

- 인원 선택: 혼자, 2명, 3~4명, 5명 이상
- 관계 선택: 친구, 연인, 가족, 동료
- 관계 선택은 선택 사항이다.
- `잘 모르겠어요` 또는 `건너뛰기`를 제공하되 내부 값은 기존 API가 처리 가능한 빈 문자열 또는 확정된 기본값을 사용한다.

#### 4단계: 목적

- 맛집
- 카페/디저트
- 놀거리
- 문화/전시
- 산책/구경
- 술/야간
- 최대 3개 선택 규칙은 유지한다.
- 최소 하나를 선택해야 다음으로 이동할 수 있다.

#### 5단계: 이용 시간

- 자동 추천을 첫 번째이자 기본 선택으로 둔다.
- 2시간
- 4시간
- 저녁까지
- 밤까지
- 종료 시간 직접 선택

#### 하단 행동 영역

- 각 단계 하단에 화면 스크롤과 무관하게 보이는 고정 행동 영역을 둔다.
- 기본 버튼 문구는 `다음`이다.
- 마지막 단계는 `조건 확인하기`이다.
- 선택이 필요한 단계에서 값이 없으면 버튼을 비활성화한다.
- 키보드가 열린 주소 입력 상태에서는 버튼이 가려지지 않아야 한다.

#### 선택 요약

- 현재 화면 하단에 모든 조건 카드를 다시 나열하지 않는다.
- 완료된 값은 상단 진행률 아래에 작은 요약 칩으로만 보여준다.
- 칩을 누르면 해당 단계로 돌아가 수정할 수 있다.

### 6.2 `/planner/condition`: 세로 요약 목록＋선택 설정

현재 여러 색상의 2열 카드가 많은 정보를 같은 무게로 보여준다. 한 줄짜리 세로 요약 목록으로 변경한다.

표시 순서:

1. 출발 위치
2. 출발 시간
3. 동행
4. 하고 싶은 것
5. 이용 시간

각 행은 다음 구조를 사용한다.

```text
[아이콘] 출발 위치
        연남동                         [수정]
```

- 값이 없으면 `미정` 대신 `선택해주세요`를 사용한다.
- 필수값이 비어 있으면 해당 행을 경고 상태로 표시한다.
- 행 전체를 누르면 기존 편집 UI 또는 해당 단계형 선택 UI가 열린다.
- `현재 위치 다시 잡기`는 출발 위치 행의 보조 행동으로 넣고 별도 큰 버튼으로 두지 않는다.

`더 맞춰볼까요?`는 선택 설정으로 유지한다.

- 도보 짧게
- 대기 적게
- 사진 예쁜 곳
- 조용한 곳
- 비 안 맞게

이 칩들은 선택 사항임을 표시하고 실제 `extras` 또는 대응 조건에 반영한다. 값에 반영되지 않는 장식용 칩은 만들지 않는다.

하단에는 `이 조건으로 코스 찾기` 버튼을 고정한다. 필수 조건이 누락되면 검색하지 않고 첫 누락 항목으로 이동시킨다.

### 6.3 `/planner/searching`: 신뢰를 주는 검색 진행 화면

- 현재 읽고 있는 조건과 단계별 진행 상태를 유지한다.
- Nopi 이미지와 진행 메시지는 한 영역으로 통합한다.
- 진행 단계는 장소 확인 → 영업시간 확인 → 동행/분위기 확인 → 취향 확인 → 이동 순서 정리 순으로 보여준다.
- 이미 완료된 단계는 체크 표시, 현재 단계는 애니메이션 또는 강조, 남은 단계는 비활성 색상으로 표시한다.
- 실제 검색 Promise가 끝나지 않았는데 가짜로 완료되었다고 표시하지 않는다.
- 검색이 길어질 때 `조건을 확인하는 데 시간이 조금 더 걸리고 있어요`라는 지연 상태를 제공한다.
- 검색 실패 시 결과 화면으로 무조건 이동하지 말고 실패 상태와 `다시 시도`, `조건 수정` 행동을 제공한다.
- 과도한 스피너나 빠르게 번쩍이는 애니메이션은 사용하지 않는다.

### 6.4 `/planner/result`: 성공·부분 성공·실패를 분리

#### 성공

상단 요약 카드에 다음 정보를 우선 표시한다.

- 코스 제목
- 총 장소 수
- 예상 이용 시간
- 총 도보 시간 또는 이동 요약
- 현재 확인 가능한 혼잡도 요약
- 추천 이유 한 문장

장소 목록은 실제 사진을 우선 사용하고 다음을 표시한다.

- 순서
- 장소명
- 카테고리
- 예상 체류 시간
- 다음 장소까지 이동 시간
- 영업 여부
- 혼잡도 데이터가 있을 때만 혼잡도

주요 CTA는 `이 코스로 출발`이며 `/course/map`으로 이동한다. `코스 저장`은 보조 행동으로 둔다.

#### 부분 성공

- 검증된 장소만 표시한다.
- 빠진 일정을 빈 카드로 만들어 채우지 않는다.
- `확인된 장소만 먼저 볼게요`라는 안내를 한 번만 표시한다.
- `조건을 넓혀 다시 찾기`와 `이 코스로 출발`을 제공한다.

#### 실패

- 같은 오류를 NopiBubble, 경고 배너, 결과 카드에 반복하지 않는다.
- 오류 메시지 영역은 한 개만 사용한다.
- 사용자에게 서버 내부 용어, API 오류, 스택 또는 원시 메시지를 노출하지 않는다.
- 행동 우선순위:
  1. `다시 찾기`
  2. `조건 수정`
- 실패 상태에서는 빈 칩, 빈 버튼, 의미 없는 코스 카드를 렌더링하지 않는다.

## 7. 탐색 UX — 현재 구현 승인 및 동결

현재 구현된 탐색 화면은 사용자 확인을 통과했다. 아래 항목은 현재 구현의 기준을 기록하기 위한 것이며, 이번 후속 수정에서 탐색 레이아웃, 카드, 필터, 문구를 다시 디자인하지 않는다.

- 코스와 마이 수정 때문에 탐색의 검색, 필터, 카드 열기 동작이 깨지지 않는지만 회귀 확인한다.
- `이 코스로 출발`과 선택 코스 연결을 위해 필요한 최소 동작 수정만 허용한다.
- 공통 CSS 수정으로 현재 탐색의 크기, 간격, 색상과 스크롤이 달라지지 않게 한다.

### 7.1 기본 구조

`/explore`는 다음 순서로 구성한다.

```text
탐색
홍대에서 인기 있는 코스

[지역, 분위기, 코스 검색]
[인기순] [조회순] [지금 가능] [실내]

이번 주 인기 코스
[코스 카드]
[코스 카드]
```

### 7.2 삭제 또는 변경할 요소

- 현재 `explore-map-card` 장식용 가짜 지도는 삭제한다.
- 실제 지도를 구현하지 않는 이번 작업에서는 지도처럼 보이는 장식 영역을 대체하지 않는다.
- 동작하지 않는 필터 버튼 또는 칩을 그대로 두지 않는다.
- 기능을 구현할 수 없는 필터는 숨긴다.
- 성수 등 홍대 DB 범위 밖의 하드코딩 fallback 코스를 제거한다.

### 7.3 검색과 필터

- 텍스트 검색은 코스명, 홍대 세부 지역명, 장소명, 분위기 태그를 대상으로 한다.
- 인기순과 조회순은 기존 API 정렬을 유지한다.
- `지금 가능`, `실내`는 응답 데이터로 정확히 판별할 수 있을 때만 노출하고 필터링한다.
- 상단 필터 아이콘을 유지한다면 바텀시트를 열어야 한다.
- 바텀시트에는 현재 데이터로 판별 가능한 필터만 넣는다.
- 적용된 필터 수를 아이콘 배지로 표시한다.
- `초기화`, `적용` 행동을 제공한다.
- 결과가 없으면 빈 흰 화면 대신 필터 초기화와 새 검색 행동을 제공한다.

### 7.4 코스 카드

각 코스 카드는 가능한 데이터 범위 안에서 다음을 표시한다.

- 대표 장소 사진 또는 최대 3장의 이미지 프리뷰
- 홍대 세부 지역
- 코스 제목
- 대표 장소 2~3개 경로
- 총 장소 수
- 예상 시간
- 좋아요 또는 저장 수
- 조회 수

실제 사진이 없으면 장소 카테고리 아이콘을 사용하되, 모든 카드가 동일한 임시 아이콘처럼 보이지 않게 한다.

### 7.5 코스 열기 동작

현재는 코스 카드를 누르면 즉시 `loadPlan`을 실행하고 `/course/map`으로 이동한다. 이를 미리보기 단계로 변경한다.

- 카드 클릭 → 코스 미리보기 모달 또는 상세 패널
- 미리보기에서 장소 순서, 시간, 이동 정보 확인
- CTA 문구는 내부 상태를 연상시키는 `사용`이 아니라 `이 코스로 출발`로 통일한다.
- `이 코스로 출발`을 누른 시점에만 `loadPlan`하고 선택된 코스 상태로 만든다.
- 선택 직후 `코스 탭에 담았어요` 같은 모호한 토스트만 띄우지 말고 `/course/map`으로 이동해 사용자가 결과를 바로 확인하게 한다.
- 미리보기를 닫으면 기존에 선택된 코스를 덮어쓰지 않는다.

기존 `ExploreDetailModal`을 재사용할 수 있으면 중복 구현하지 않는다.

## 8. 코스 UX 개편

### 8.1 선택된 코스 상태를 명시적으로 관리

현재 `PlannerContext`는 시작 시 fallback plan을 만들기 때문에 사용자가 코스를 선택하지 않아도 코스 탭에 제목과 빈 지도가 나타날 수 있다.

코드 내부에는 `hasActivePlan` 또는 동등한 명시적 상태를 추가할 수 있다. 단, 사용자 화면과 안내 문구에는 `활성 코스`, `코스 활성화`라는 개발 용어를 사용하지 않는다. 사용자에게는 `선택한 코스`, `진행할 코스`, `이 코스로 출발`이라고 표현한다.

코스가 선택되는 경우는 아래 세 가지로 고정한다.

1. 검색 결과에서 `이 코스로 출발`을 누른 경우
2. 탐색 코스 미리보기에서 `이 코스로 출발`을 누른 경우
3. 마이페이지의 저장 또는 최근 코스에서 `코스로 열기`를 누른 경우

단순히 검색 결과 화면을 보거나 탐색 카드를 눌러 미리보기만 연 상태에서는 코스 탭의 기존 코스를 변경하지 않는다.

- 초기값: `false`
- 검색 결과에서 `이 코스로 출발`을 눌렀을 때: `true`
- 탐색 미리보기에서 `이 코스로 출발`을 눌렀을 때: `true`
- 마이페이지에서 `코스로 열기`를 눌렀을 때: `true`
- 사용자가 코스를 초기화했을 때: `false`
- API 실패 또는 검증된 장소가 0개인 계획은 선택된 코스로 취급하지 않는다.

기존 fallback 데이터가 UI에서 실제 사용자 코스처럼 노출되지 않게 한다.

### 8.2 선택한 코스가 없을 때

`/course/map`에 다음 빈 상태를 보여준다.

```text
아직 선택한 코스가 없어요
검색 결과에서 ‘이 코스로 출발’을 누르거나
탐색에서 마음에 드는 코스를 골라보세요.

[코스 추천받기]
[탐색에서 둘러보기]
```

- `코스 추천받기`는 홈으로 이동한다.
- `탐색에서 둘러보기`는 `/explore`로 이동한다.
- 지도, `결과로`, 카카오 길찾기 버튼은 렌더링하지 않는다.
- 빈 상태 설명만 읽어도 무엇을 해야 코스 탭에 코스가 생기는지 이해할 수 있어야 한다.
- `활성화`, `활성 코스`라는 표현은 표시하지 않는다.

### 8.3 선택한 코스가 있을 때

화면은 지도＋코스 진행 패널 구조로 변경한다.

- 상단: 코스 제목, 세부 지역, 장소 수, 예상 총시간
- 지도: 전체 경로와 장소 순서 마커
- 하단 패널: 현재 장소, 다음 장소, 전체 장소 목록
- 주요 행동: `카카오맵으로 길찾기`
- 보조 행동: `장소 바꾸기`, `장소 상세`

`결과로` 버튼은 주요 행동처럼 보이지 않게 텍스트 또는 보조 버튼으로 내린다.

### 8.4 장소 상세와 교체

`/course/place/:index`:

- 실제 사진 갤러리를 가장 먼저 보여준다.
- 장소명, 카테고리, 영업 여부, 혼잡도, 추천 이유, 이동/대기/무드를 묶어서 보여준다.
- `카카오맵 길찾기`를 주요 CTA로 유지한다.
- `다른 장소로 바꾸기`를 보조 CTA로 둔다.

`/course/replace/:index`:

- 현재 장소를 상단에 작게 표시한다.
- 후보 카드마다 기존 장소 대비 차이를 표시한다.
  - 이동 시간 변화
  - 분위기 또는 카테고리
  - 혼잡도
- `바꾸기`를 누르기 전에는 plan을 변경하지 않는다.
- 바꾼 뒤 `/course/map`으로 돌아가고 변경 완료 안내를 보여준다.
- 후보가 없으면 조건 수정 또는 현재 코스 유지 행동을 제공한다.

## 9. 마이 UX 개편

### 9.1 비로그인 상태

현재처럼 큰 흰 카드 하나와 로그인 버튼만 표시하지 않는다. 화면 전체를 사용해 로그인 가치를 설명하되 인증 방식은 변경하지 않는다.

```text
마이

[Nopi 아이콘]
코스를 저장하고 다시 꺼내보세요
저장한 코스와 최근 본 코스를 한 곳에서 관리할 수 있어요.

[로그인하기]

로그인하면 가능한 것
- 저장한 코스 보관
- 최근 본 코스 확인
- 방문 기록 관리
```

- 기존 `/login` 이동을 유지한다.
- 사용자를 속이는 임시 코스 수나 가짜 통계를 표시하지 않는다.
- 하단 네비게이션 위에 불필요한 큰 빈 공간이 남지 않게 중앙 정렬 또는 균형 있는 상단 배치를 사용한다.

### 9.2 로그인 상태

로그인 후 마이페이지는 여러 메뉴와 목록을 세로로 이어 붙이는 대시보드 형태로 만들지 않는다. 기존의 `저장 / 최근 / 방문` 탭 방식이 더 빠르게 비교되므로 이를 필수로 유지한다.

화면 구조는 다음과 같이 고정한다.

```text
마이                                      [설정]
[작은 프로필] 사용자명
             계정 정보

[저장한 코스 3] [최근 본 코스 5] [방문 2]
────────────────────────────────────
현재 선택된 탭의 목록만 표시
[코스 카드]
[코스 카드]
```

- 프로필 영역은 한 줄 또는 최대 2줄의 압축된 헤더로 만들고 큰 프로필 패널로 화면 상단을 차지하지 않는다.
- 저장, 최근, 방문 탭은 가로 한 줄의 세그먼트 탭으로 고정한다.
- 탭이 두 줄로 줄바꿈되지 않게 한다.
- 선택한 탭의 목록 하나만 DOM과 화면에 표시한다.
- 저장 목록 아래에 최근 목록과 방문 목록을 세로로 이어서 렌더링하지 않는다.
- 탭을 바꾸면 목록 상단부터 보여주고, 다른 탭의 목록은 숨긴다.
- 첫 화면에서 프로필, 탭과 첫 번째 코스 카드 일부가 함께 보여야 한다.
- 탭 이름 옆의 개수는 실제 데이터가 있을 때만 표시한다.
- 백엔드에서 방문 기록을 받지 못하면 `방문` 탭을 비활성화 상태로 두지 말고 숨긴다.
- 포인트와 여행 성향이 실제 값과 기능에 연결되지 않으면 이번 화면에서 숨긴다.
- 설정 버튼은 우측 상단에 두고 로그아웃은 설정 안의 텍스트 행동으로 이동한다.
- 빈 목록은 가짜 코스 객체를 렌더링하지 않고 전용 빈 상태 컴포넌트를 사용한다.

빈 상태 예시:

```text
아직 저장한 코스가 없어요
탐색에서 마음에 드는 홍대 코스를 찾아보세요.
[탐색으로 이동]
```

### 9.3 내 코스 카드 동작

- 카드의 주요 행동 문구는 `보기`보다 동작이 명확한 `코스로 열기`를 사용한다.
- 현재 `보기`가 무조건 `/explore`로 이동하는 동작을 수정한다.
- 코스에 장소 데이터가 있으면 `코스로 열기`를 누른 시점에 해당 데이터를 `loadPlan`하고 선택된 코스 상태로 만든 뒤 `/course/map`으로 이동한다.
- 필요한 장소 데이터가 없으면 코스 상세 조회 API를 사용한 뒤 연다.
- 상세 조회도 실패하면 오류 안내와 다시 시도를 제공하며 탐색 화면으로 임의 이동시키지 않는다.

## 10. 데이터 및 상태 표현 규칙

### 10.1 홍대 범위 고정

- 사용자에게 노출되는 탐색 fallback, 예시 코스, 현재 코스는 홍대입구·연남동·상수·합정 권역만 사용한다.
- DB에 없는 외부 지역 코스를 프론트에서 만들어내지 않는다.
- 현재 위치가 외부 지역이면 서비스 가능 권역을 선택하도록 안내한다.

### 10.2 실제 데이터와 placeholder 구분

- 실제 지도가 없는데 지도처럼 보이는 그래픽을 보여주지 않는다.
- 실제 장소 사진이 없으면 이미지 영역에 카테고리 fallback임을 시각적으로 명확히 한다.
- 검증된 장소가 없는데 추천 코스가 존재하는 것처럼 제목과 CTA를 표시하지 않는다.
- 빈 상태를 가짜 데이터 객체로 구현하지 않는다.

### 10.3 혼잡도

- 데이터가 있을 때만 혼잡도 배지를 표시한다.
- `여유`, `보통`, `약간 붐빔`, `붐빔`, `정보 없음` 표현은 기존 혼잡도 기획 문서의 정책을 따른다.
- `정보 없음`은 추천 실패나 장소 제외 사유로 사용하지 않는다.
- 정확한 인원수처럼 보이는 표현을 추가하지 않는다.

### 10.4 로딩·오류·빈 상태

모든 API 기반 목록과 상세 화면에 다음 상태를 구분한다.

```text
idle
loading
success with data
success with empty data
error
```

- 로딩 중에는 이전 데이터와 빈 상태가 동시에 보이지 않아야 한다.
- 오류를 `alert()`로 처리하지 않는다.
- 오류 문구에는 사용자가 취할 수 있는 다음 행동이 있어야 한다.
- 같은 오류를 한 화면에 반복 표시하지 않는다.

## 11. 접근성 및 인터랙션

- 아이콘만 있는 버튼에는 `aria-label`을 제공한다.
- 선택 칩은 시각 상태뿐 아니라 `aria-pressed` 또는 적절한 선택 상태를 제공한다.
- 바텀시트와 모달은 열릴 때 내부로 포커스를 이동하고 닫힐 때 원래 버튼으로 돌려준다.
- ESC와 배경 클릭으로 닫을 수 있게 하되 적용 전 선택을 저장하지 않는다.
- 색상만으로 선택, 성공, 오류를 구분하지 않는다.
- 본문 대비는 WCAG AA 수준을 목표로 한다.
- `prefers-reduced-motion`에서 진행 애니메이션을 줄인다.

## 12. 구현 순서

한 번에 전부 섞어서 수정하지 말고 아래 순서로 진행한다.

### 1차: 검색 흐름

- `/planner/chat` 단계형 UX
- `/planner/condition` 요약 목록
- `/planner/searching` 진행·지연·실패 상태
- `/planner/result` 성공·부분 성공·실패 분리

### 2차: 코스

- 명시적인 선택 코스 상태와 선택 진입점
- 코스 빈 상태
- 지도＋진행 패널
- 장소 상세·교체 동작

### 3차: 탐색 회귀 확인

- 현재 승인된 탐색 디자인 유지
- 검색·필터·카드 회귀 확인
- `이 코스로 출발`과 선택 코스 연결만 확인

### 4차: 마이 및 시각 통일

- 로그인 전/후 화면
- 가짜 빈 코스 제거
- 저장·최근 코스 열기 수정
- 비홈 화면의 색상, 타이포, 카드, 버튼 통일

## 13. 테스트 시나리오

### 검색

- [ ] 첫 단계에서 뒤로가면 홈으로 이동한다.
- [ ] 중간 단계에서 뒤로가면 값이 보존된다.
- [ ] 필수값 없이 다음 단계로 갈 수 없다.
- [ ] 직접 주소 입력 시 서비스 범위 밖 주소를 안내한다.
- [ ] 목적은 최대 3개까지만 선택된다.
- [ ] 조건 확인에서 각 항목을 수정할 수 있다.
- [ ] 검색 지연, 성공, 부분 성공, 실패가 각각 구분된다.
- [ ] 실패 오류가 한 번만 표시된다.

### 탐색

- [ ] 홍대 범위 밖 fallback 코스가 표시되지 않는다.
- [ ] 보이는 필터는 모두 실제로 동작한다.
- [ ] 검색 결과가 없을 때 초기화 행동이 보인다.
- [ ] 카드 클릭만으로 기존에 선택된 코스가 바뀌지 않는다.
- [ ] 미리보기에서 적용한 뒤에만 코스 탭이 변경된다.
- [ ] `이 코스로 출발`을 누르면 선택 상태가 저장되고 코스 화면으로 이동한다.

### 코스

- [ ] 앱 첫 진입 후 코스 탭에 가짜 fallback 코스가 표시되지 않는다.
- [ ] 선택한 코스가 없으면 지도와 길찾기 버튼이 표시되지 않는다.
- [ ] 빈 상태에서 코스를 선택하는 세 가지 방법을 사용자가 이해할 수 있다.
- [ ] 결과 또는 탐색에서 선택한 코스가 정확히 열린다.
- [ ] 사용자 화면에 `활성`, `활성화`라는 개발 용어가 노출되지 않는다.
- [ ] 장소 교체 전후 데이터가 정확히 유지된다.
- [ ] 카카오맵 경로에 좌표가 있는 장소만 전달된다.

### 마이

- [ ] 비로그인 상태에서 로그인 버튼이 `/login`으로 이동한다.
- [ ] 로그인 상태에서 저장·최근 데이터를 구분한다.
- [ ] 저장·최근·방문 목록이 한 페이지에 세로로 연속 노출되지 않는다.
- [ ] 한 번에 선택한 탭의 목록 하나만 보인다.
- [ ] 데이터가 없는 탭은 가짜 코스가 아니라 빈 상태를 보여준다.
- [ ] `코스로 열기`를 누르면 해당 코스가 선택되고 코스 화면으로 이동한다.
- [ ] 상세 조회 실패 시 탐색으로 임의 이동하지 않는다.

### 회귀 및 반응형

- [ ] 홈 화면 구조와 동작이 변경 전과 같다.
- [ ] 320px, 360px, 390px, 430px 너비에서 가로 스크롤이 없다.
- [ ] 모바일 키보드가 단계형 화면의 주요 버튼을 영구적으로 가리지 않는다.
- [ ] 하단 네비게이션과 콘텐츠가 겹치지 않는다.
- [ ] 데스크톱 휴대폰 프레임에서도 잘리지 않는다.
- [ ] 모든 활성 화면에 치명적인 콘솔 오류가 없다.

## 14. 완료 기준

다음을 모두 만족해야 완료로 본다.

- [ ] 홈 화면 구조와 기능을 수정하지 않음
- [ ] 검색 입력이 한 화면에 하나의 질문만 보이는 단계형 UX로 변경됨
- [ ] 조건 확인 화면에서 필수 조건과 선택 조건이 구분됨
- [ ] 결과 성공·부분 성공·실패 상태가 명확히 분리됨
- [ ] 탐색의 가짜 지도와 작동하지 않는 UI가 제거됨
- [ ] 탐색 코스는 미리보기 후에만 현재 코스로 적용됨
- [ ] 선택한 코스가 없을 때 선택 방법을 설명하는 전용 빈 상태가 표시됨
- [ ] fallback plan이 실제 코스처럼 노출되지 않음
- [ ] 마이페이지가 가짜 코스 객체를 사용하지 않음
- [ ] 마이페이지가 저장·최근·방문 탭 중 하나의 목록만 표시함
- [ ] 내 코스의 `코스로 열기`가 해당 코스를 실제로 선택하고 엶
- [ ] 홍대 범위 밖 예시 및 fallback이 노출되지 않음
- [ ] 장소 사진, 혼잡도, 영업 정보는 실제 데이터가 있을 때만 표시됨
- [ ] 비홈 화면의 디자인 언어가 통일됨
- [ ] `npm run build` 성공
- [ ] `npm run lint`에서 이번 작업으로 추가된 오류가 없음

## 15. 개발 완료 보고 형식

개발 완료 후 다음 내용을 보고한다.

```text
1. 수정한 파일 목록
2. 검색 / 탐색 / 코스 / 마이별 변경 요약
3. 새로 추가한 상태 또는 컴포넌트
4. API 또는 기존 데이터 구조 때문에 구현하지 못한 항목
5. 모바일 확인 너비와 결과
6. npm run build 결과
7. npm run lint 결과
8. 홈 화면 비변경 회귀 확인 결과
```

문서에 없는 백엔드 변경이나 새로운 서비스 범위 확장은 임의로 진행하지 않는다. 기존 응답만으로 구현할 수 없는 요구사항은 가짜 데이터로 채우지 말고, 해당 항목과 필요한 데이터 필드를 완료 보고에 명확히 남긴다.
