# 중심 관광지에 여행코스·쇼핑 추가

## 반영 범위

- 중심 관광지 검색에 여행코스(25), 쇼핑(38)을 추가했다. 관광지(12), 문화시설(14), 레포츠(28)는 유지한다.
- 축제·공연·행사(15), 숙박(32), 음식점(39)은 이번 검색/중심 일정 저장 대상에서 제외한다.
- 울산의 전체·인기순·맞춤 추천순·이름순에 새 분류도 포함한다. 다른 지역에서도 두 분류의 TourAPI 키워드 검색이 가능하다.
- 선택 → 체류시간 설정 → 일정에 담기 → 저장·다시 열기에서 분류와 대표 좌표를 유지한다.
- 여행코스는 대표 좌표를 가진 하나의 중심 일정으로 담는다. 여러 경유지를 자동 전개하지 않는다. 주변 추천 역시 대표 좌표 기준이며, 선택 화면에 이 내용을 안내한다. 여러 장소를 이동하는 전체 코스 경로/소요시간을 검증했다고 표시하지 않는다.
- 분류 버튼은 화면 폭에 맞춰 줄바꿈하며 기존 PC 3열 카드 목록을 유지한다.

## 울산 공개 데이터 갱신

2026-09-19에 기존 165개 항목을 유지하면서 신규 분류를 공식 TourAPI 지역 목록 및 `울산`/`울주` 키워드 검색으로 보충했다.

| 분류 | 항목 수 |
|---|---:|
| 관광지 | 131 |
| 문화시설 | 16 |
| 레포츠 | 18 |
| 여행코스 | 2 |
| 쇼핑 | 107 |
| 전체 | 274 |

이 수는 현재 수집한 유효 항목 수이며 울산의 모든 관광 자원을 망라한다는 뜻은 아니다. 지역 목록에서 여행코스는 0건이지만 키워드 검색에는 별도 항목이 있었다. 울산 주소·구/군과 국내 유효 좌표를 확인할 수 있는 항목만 포함했다. 주소가 비었거나 대표 위치가 부산인 복수 지역 코스, 좌표가 0인 코스는 울산 목록에 넣지 않았다.

쇼핑은 공식 분류를 그대로 사용하므로 전통시장뿐 아니라 백화점·브랜드 매장도 포함한다. 제공기관에서 같은 이름을 다른 콘텐츠 ID/분류로 등록한 항목은 임의로 합치지 않는다.

쇼핑은 기존 데이터랩 CSV의 같은 구/군·정규화한 이름이 유일하게 일치할 때만 통계를 연결한다. 여행코스에는 단일 장소의 통계를 붙이지 않는다. 미연결 값은 null로 보존하고 화면에 자료 없음을 표시한다. 통계가 없는 항목끼리는 이름순으로 정렬한다.

## 배포

프론트와 백엔드를 함께 반영해야 한다. DB 스키마 변경은 없다.

- 프론트: `src/api/tourismApi.ts`, `src/features/trips/TourismPicker.tsx`, `tourismPicker.css`, `tourismModel.ts`, `tripModel.ts`를 포함한 빌드 배포.
- 백엔드: `routes/tourism/service.js`, `routes/tourism/ulsan.js`, `routes/trips/validation.js`, `data/tourism/ulsan-tourapi.json` 반영 후 재시작. 울산 목록은 프로세스 시작 시 JSON을 읽는다.
- 수집 스크립트 `scripts/fetch-ulsan-tourism.cjs`도 갱신했다. 아래 명령은 기존 세 분류를 유지하며 새 두 분류를 다시 수집한다. 옵션 없이 실행하면 다섯 분류 전체를 갱신한다.

```powershell
# D:/Backend/NoPlan에서 실행. 기존 .env의 PUBLIC_DATA_SERVICE_KEY 사용.
node scripts/fetch-ulsan-tourism.cjs --expand-types
```

운영 배포는 수행하지 않았다.

## 검증

- 백엔드 관광 검색·울산 정렬·여행 저장 관련 테스트 21개 통과.
- 프론트 관광지 일정 모델 테스트 4개 통과, 변경 TS/TSX ESLint 및 프로덕션 빌드 통과.
- 실제 브라우저에서 전체 274개 → 여행코스 2개 → 120분 선택 → 다시 열기 → 쇼핑 107개/인기순 → 언양알프스시장으로 변경 확인.
- PC 화면에서 여섯 분류 탭과 3열 사진 카드 레이아웃 확인.
- 미리보기: `http://127.0.0.1:5198/dev-preview/ulsan-tourism.html` (20대 여성 샘플 회원, 운영 계정/DB 저장 없음).

## 카드 상세정보 패널 추가

카드를 선택하면 같은 화면 오른쪽에서 상세정보를 읽는다. 검색 조건과 목록 스크롤은 유지하고, 선택이 바뀔 때 오른쪽 스크롤만 맨 위로 초기화한다. 소개는 더 보기로 펼칠 수 있고, 일정에 담기 버튼은 아래에 고정한다.

- 새 `GET /api/tourism/:contentId?type=...`에서 TourAPI `detailCommon2`, `detailIntro2`, `detailInfo2`를 병렬 조회한다.
- 장소 소개, 이용시간, 휴무일, 요금, 문의, 주차, 공식 홈페이지 및 분류별 추가 안내 중 등록된 값을 보여준다.
- 여행코스는 전체 코스의 기간·거리와 순서별 경유지를 보여주고 각 경유지의 설명을 펼칠 수 있다. 코스의 전체 기간과 사용자가 입력하는 구간 배정 시간을 구분한다. 경유지 자동 추가 기능은 아니다.
- 네이버지도 검색, 카카오맵 위치 확인, 제공된 공식 홈페이지는 새 탭으로 열린다. 네이버 링크는 지역·이름 검색이며 특정 업체 상세 페이지와의 매칭을 보장하지 않는다.
- 상세정보가 없거나 조회에 실패해도 지도 링크와 기존 일정 담기는 사용할 수 있다. 일부 API 실패는 확인된 정보만 표시하고 재시도 버튼을 제공한다. 누락된 요금을 무료로 표시하지 않는다.
- 선택한 카드만 상세 조회하고, 서버에서 같은 요청을 합치며 완전한 응답만 15분간 캐시한다. 일부 실패 응답은 재시도를 위해 캐시하지 않는다. 카드 변경 시 이전 요청을 취소하고 이전 설명은 즉시 제거한다.
- 외부 HTML을 직접 렌더링하지 않고 텍스트로 정규화한다. 홈페이지는 인증정보 없는 HTTP(S) URL만 허용한다. API 키 및 제공기관 오류 원문은 응답하지 않는다.

배포에는 프론트 새 `TourismDetails.tsx`와 API/선택창/CSS 변경, 백엔드 새 `routes/tourism/details.js`와 `service.js`/`router.js` 변경이 필요하다. 기존 `PUBLIC_DATA_SERVICE_KEY`를 사용하며 DB 변경은 없다. 프론트·백엔드를 함께 배포하고 백엔드를 재시작한다. `scripts/preview-ulsan-tourism.cjs`는 운영 DB 없이 실제 상세 API를 사용하는 로컬 확인용이다.

검증: 관광 검색·정렬·상세 API 관련 19개 테스트, 변경 파일 ESLint 및 빌드 통과. 브라우저에서 태화강생태관의 소개/이용정보, 여행코스의 1박2일·25.5km·경유지 5곳, 경유지 설명 펼치기, 빠른 카드 전환, 오른쪽 독립 스크롤과 고정 담기 버튼을 확인했다. 운영 배포는 수행하지 않았다.

## 상세 크게 보기

오른쪽 패널 상단의 `상세 크게 보기`를 누르면 같은 선택창의 전체 폭으로 상세정보를 펼친다. 장소 이름·큰 사진과 소개·방문 정보를 두 열로 배치하고, 소개 전문과 큰 글씨를 제공한다. 머무는 시간과 일정 담기 버튼은 하단에 고정한다.

`목록으로 돌아가기`는 기존 검색 조건, 선택 장소, 시간 입력과 목록·우측 패널의 스크롤 위치를 복원한다. 목록 화면의 카드 크기는 유지하며 새 창이나 별도 경로를 만들지 않는다. 이번 확장 보기 자체는 프론트 변경이다.

검증: ESLint 및 프로덕션 빌드 통과. 1280×720 브라우저에서 상세 확대, 하단 이용정보 스크롤, 120분 선택 유지, 목록 스크롤 342px 복원 및 기존 목록 폭 유지 확인.
