# PC 홈 화면과 콘텐츠 관리 방향

## 이번 변경

- GNB 및 `TripHome`의 여행 만들기 폼(날짜·동행·이동수단·관광지 선택·생성 로직)은 유지했다.
- 첫 배너는 기존 해안 이미지와 문구를 사용한다. 왼쪽 어두운 그라데이션, 양옆 미리보기, 이전/다음 버튼, 페이지 버튼과 번호를 추가했다. 자동 재생은 하지 않는다.
- 축제 배너는 기존 `/api/events?kind=festival&from=오늘&to=오늘&sort=ending`을 사용한다. 한국 날짜 기준 개최 기간 안에 있고 취소되지 않은, 이미지가 있는 축제를 최대 4개 고른다. 첫 페이지 후보 안에서 지역이 겹치지 않는 항목을 우선한다. 데이터가 없으면 기본 여행 배너만 표시하며, 요청 실패 시 행사 목록 링크를 제공한다.
- 전시 배너는 CSS 티켓·액자·추상 포스터로 구성했다. 실제 전시 포스터로 오인할 제목·일정을 넣지 않았다. 클릭하면 기존 `/app/events?kind=exhibition`으로 이동한다.
- 하단은 사진이 있는 4열 카드로 구성했다. 현재 공개 이용자 여행기 데이터가 없으므로 제목은 `국내 여행 추천코스`다. 제주·강릉·서울·울산의 실제 TourAPI 여행코스 ID와 경유지 사진을 연결했다. 카드 편집 문구 및 대표 경유지 목록은 `src/features/trips/homeContent.ts`에 있고, 상세는 기존 `/api/tourism/:id?type=25`에서 조회한다. 카드에 표시한 시간은 관광공사 제공값이다.
- 전체 보기는 현재 소개하는 4개 코스를 모아 보여준다. 상세에는 전체 경유지 설명과 네이버지도 검색 링크가 있다. 코스 전체를 자동으로 개인 일정에 복사하는 기능은 이번 범위에 없다.

## 배너를 직접 관리하려면 (다음 단계 제안, 아직 미구현)

현재 `noplan_event_catalog`는 제공기관별 JSON 수집본이며 갱신 때 교체된다. 배너 순서나 문구를 이 테이블에 직접 넣으면 갱신 때 사라질 수 있다. 별도 `noplan_home_banners` 테이블을 두는 것이 좋다.

권장 필드: `id`, `event_id`, `title_override`, `subtitle_override`, `image_url`, `image_credit`, `sort_order`, `is_active`, `display_from`, `display_until`, `updated_at`.

관리 흐름:

1. 관리자 전용 화면에서 기존 축제를 검색해 선택한다. 기존 관리자 인증·권한을 재사용한다.
2. 배너 문구·가로 이미지·노출 시작/종료·순서를 지정하고 미리본다.
3. 저장하면 서버의 홈 공개 조회 API가 활성 배너만 반환한다. 운영자는 코드 재배포 없이 순서와 내용을 변경한다.
4. 서버는 DB 노출 기간뿐 아니라 원본 축제의 취소 여부와 개최 기간도 검사한다. 끝난 축제는 자동으로 빠진다. 지정 배너가 부족하면 지금의 자동 선정으로 보충한다.

현재는 자동 선정이 연결된 상태다. 이 관리 테이블, 관리자 CRUD, 공개 홈 API는 아직 만들거나 운영 DB에 적용하지 않았다.

## 국내 여행기 / 추천코스 DB 연결 추천

첫 단계는 운영팀이 관리하는 `noplan_featured_courses`를 권장한다. 관광공사 추천코스와 팀이 직접 검토한 노피 코스를 먼저 등록하고, 이후 이용자가 공개 동의한 여행기를 함께 노출한다.

권장 필드: `id`, `source_type` (`tourapi` / `editorial` / `user`), `source_id`, `title`, `region`, `summary`, `cover_image_url`, `image_credit`, `duration_label`, `public_course_document`, `status` (`draft` / `published` / `hidden`), `sort_order`, `published_at`.

- `public_course_document`는 기존 여행 일정 형식에서 날짜별 장소·순서·체류시간만 추린 공개용 스냅샷으로 저장한다. 원본 개인 여행 문서를 직접 공개하지 않는다.
- 회원·동행자 정보, 초대 링크, 개인 메모는 공개 스냅샷에서 제외한다. 이용자가 공개한 코스만 승인 후 노출한다.
- 홈은 `published` 목록의 대표 사진·요약만 조회하고, 상세 진입 때 날짜별 일정을 조회한다.
- `이 코스로 여행 만들기`는 원본을 수정하지 않고 새 여행 ID와 날짜로 복사하는 방식이 적합하다.
- 사용자 여행기가 쌓이면 `추천코스 / 여행기` 탭으로 구분하고 여행기는 공개 시각 최신순으로 표시한다. 방문 인증이나 실제 후기 데이터가 없는 코스에 `직접 다녀온`, `실시간 인기` 같은 표시는 붙이지 않는다.

지금 4개 편집 레코드는 `homeContent.ts`에 분리되어 있어 추후 공개 홈 API 응답으로 교체하기 쉽다. 위 DB 설계는 제안이며 아직 구현·마이그레이션하지 않았다.

## 로컬 미리보기

`/dev-preview/home.html`은 실제 GNB와 홈 컴포넌트를 사용한다. `dev-preview/serve-home.cjs`는 `NOPLAN_BACKEND_PATH`(기본 `D:/Backend/NoPlan`)의 기존 관광·행사 라우터와 공개 API를 이용한다. 행사 스냅샷은 메모리에만 보관하고 MySQL에 연결하지 않는다. API 포트는 4318이며 프론트의 `VITE_APP_API_URL`을 해당 로컬 주소로 맞춘다. 이 스크립트와 HTML은 운영 빌드 진입점이 아니다.
