# 직접 장소 검색과 지도 지정

## 사용 흐름

- 노피의 코스플래닝의 **장소 담기 / 장소 변경·상세**, 일정 카드의 **장소 변경**, 오른쪽 장소 편집의 **추가 / 수정**, 하루 동선 보기의 **장소 교체**에서 사용한다.
- 관광공사 추천 목록 상단의 **장소 직접 검색**으로 이동한다. 직접 등록한 장소를 다시 수정하면 검색 화면이 바로 열린다.
- 지역·장소명으로 검색하고 주소와 지도 핀을 확인한 뒤 머무는 시간을 정한다. 전체/음식점/카페/관광명소/문화시설/숙소 분류와 페이지 이동을 지원한다. 분류는 카카오 기준이므로 결과가 없으면 전체 장소로 검색한다.
- **지도에 직접 지정**에서는 장소명·분류를 입력하고 주소 검색 또는 지도 클릭으로 좌표를 지정한다. 좌표 없는 장소는 새로 추가할 수 없다.
- 카카오는 상세 장소 링크, 네이버는 이름·주소 검색 링크를 제공한다. 네이버 검색 결과 직접 수집이나 지도 공유 URL 가져오기는 이번 범위에 포함하지 않는다.

## 동작과 저장

- 기존 카카오 지도 JavaScript SDK의 Places / Geocoder를 사용한다. 기존 등록 도메인·지도 앱 설정이 필요하며, 신규 키·구독·백엔드 API는 추가하지 않는다. SDK 검색 쿼터는 기존 앱의 사용량에 포함된다.
- 검색 장소는 source=manual, candidateSource=live, 좌표·주소·분류·카카오 상세 URL을 기존 TripPlace에 저장한다. 직접 지정은 source=manual과 지도 좌표 링크를 저장한다. 전체 장소 DB에 수집·검증 등록하지 않는다.
- 사진·운영시간·가격은 카카오 검색 응답에서 제공되지 않아 확인 완료로 표시하지 않는다. 지도 상세 링크로 안내한다. 기존 사진 준비 중 표시를 사용한다.
- 카카오 장소 ID, 관광공사 contentId, 공백 등을 정리한 동일 이름과 100m 이내 좌표를 이용해 여행 전체의 중복을 확인한다. 공급자별 명칭이 다른 장소까지 완전하게 매칭하는 기능은 아니다.
- 노피 코스에서는 교체 후 앞뒤 이동을 기존 경로 API로 재조회하고 도착·종료 시간을 다시 계산한다. 일정 카드와 하루 동선 보기는 기존 시간대를 유지하며 하루 동선에서 새 이동시간을 확인한다.
- 교체한 장소의 오래된 자동 운영 안내·이동 안내를 제거하고 사용자 메모는 보존한다. 카페 체류시간은 최소 30분이다.
- DB 스키마나 백엔드 파일 수정 없음. 현재 노피 기능을 배포한 환경에서 프론트 배포로 적용한다.

## 검증

- 빌드 성공, 관련 테스트 28개 통과. 기존 eslint-disable 경고 1건과 번들 크기 안내는 유지.
- 기존 백엔드 validateTrip으로 카카오 장소와 수동 지도 지정 장소의 저장 형식 검증. 운영 DB 쓰기 없음.
- 브라우저: 스타벅스 울산국가정원점 검색 → 중간 노드 교체 → 실제 이동시간 재조회 → 일정 반영 → 다시 열기.
- 브라우저: 같은 장소 재검색 시 첫날·둘째 날 모두 중복 비활성화 확인.
- 브라우저: 주소로 위치 이동 → 지도 클릭으로 핀 조정 → 직접 지정 관광지 추가 → 다음 날 이동.
- 브라우저: 대왕암공원 무장애나눔길 검색·추가 및 일정 카드에서 체류시간 변경 확인.
